## 1. Tóm tắt luồng sản phẩm (1 bước tự động)

Mục tiêu là **đơn giản và nhanh tối đa** cho người dùng:
- Người dùng tải file (`.xlsx` từ Mazii/Excel, `.csv`, `.tsv`) hoặc dán danh sách từ trực tiếp → chọn **Thêm vào bộ có sẵn** hoặc **Tạo bộ mới** → bấm **Nhập ngay**.
- **Không** có màn hình bắt người dùng chọn từng nghĩa thủ công. BE tự đối chiếu theo **mặt chữ + từ loại** (và phiên âm nếu file có), tự chọn nghĩa phổ biến nhất (M10.5/M4.5) và lưu thẳng vào sổ tay.
- Từ nào không khớp được trong từ điển sẽ được BE trả rõ trong mảng `not_found` → FE hiển thị thông báo rõ ràng danh sách các từ đó kèm nút **Sao chép danh sách** để người dùng biết và không bị mất dấu.

### Điểm vào trên giao diện (`LanGoo-User`)
1. **Màn danh sách sổ tay** (`src/pages/collections/index.tsx`, `src/components/collections/NotebooksToolbar.tsx`):
   - Thêm nút **"Nhập danh sách"** cạnh nút tạo bộ mới / bộ mẫu.
   - Mở dialog mặc định ở chế độ **Tạo bộ mới** (cho phép chuyển sang *Thêm vào bộ có sẵn*).
2. **Màn chi tiết một sổ tay** (`src/pages/collections/detail.tsx`, `src/components/collections/CollectionHeader.tsx` hoặc `CollectionItemsToolbar.tsx`):
   - Thêm nút **"Nhập danh sách"** mở cùng dialog, mặc định chọn sẵn chế độ **Thêm vào bộ có sẵn** với `collectionId` hiện tại (vẫn cho chuyển sang *Tạo bộ mới* nếu muốn).

## 2. Hợp đồng API (Contract)

Cả hai endpoint đều dùng **Bearer token** (`api` axios client hiện tại trong `src/api/client.ts`). Nên đặt timeout `60_000` ms (tương tự `DECK_COPY_TIMEOUT_MS` cho thao tác ghi lô).

### 2.1. Tạo bộ mới và nhập luôn trong 1 bước

- **Route:** `POST /v1/collections/import`
- **Request body:**

```json
{
  "name": "Kanji Shit",
  "description": "Import từ Mazii",
  "profile_id": "019...",
  "status": "learning",
  "items": [
    {
      "word": "支える",
      "phonetic": "ささえる つかえる",
      "mean": "chống đỡ; nâng đỡ...",
      "note": "gặp trong N2",
      "type": "word"
    },
    { "word": "bank", "pos": "n" },
    { "word": "性質（せいしつ）" }
  ]
}
```

- **Quy tắc quan trọng:**
  - Truyền `profile_id` từ `useProfileScope().profileId` (nếu có) để bộ mới gắn đúng hồ sơ đang học (tránh lệch hồ sơ khi user có nhiều profile).
  - Nếu **0 từ nào khớp** trong từ điển: BE **không tạo collection rỗng** và trả **`422 Unprocessable Entity`** với `code: "IMPORT_NO_MATCHED_ITEMS"` kèm `details.not_found` để FE vẫn hiển thị đầy đủ danh sách từ không tìm thấy.

### 2.2. Nhập vào bộ sưu tập có sẵn

- **Route:** `POST /v1/collections/:collectionId/items/import`
- **Request body:**

```json
{
  "status": "learning",
  "items": [
    { "word": "性質", "pos": "noun", "reading": "せいしつ", "note": "" },
    { "word": "khongtontai" }
  ]
}
```

- **Quy tắc quan trọng:**
  - Luôn trả `201 Created` kể cả khi `added_count === 0` (toàn trùng hoặc toàn không có trong từ điển).
  - Tự bỏ qua các từ đã có trong bộ (`skipped_duplicates`, `reason: "already_in_collection"`).

### 2.3. Ràng buộc từng trường đầu vào (`items[]`)

| Field | Kiểu | Bắt buộc | Giới hạn & Ghi chú |
| :--- | :--- | :---: | :--- |
| `items` | `array` | ✅ | `1..500` phần tử/request. Nếu file > 500 dòng, FE chia lô tuần tự (xem §5) |
| `items[].word` | `string` | ✅ | `1..120` ký tự sau trim. BE tự tách ngoặc kiểu `"性質（せいしつ）"` hoặc `"bank (n)"` |
| `items[].pos` | `string` | — | Tối đa `40` ký tự. Hỗ trợ viết tắt EN/VI/JA (`n`, `v`, `adj`, `danh từ`, `動詞`…). Nếu lệch từ loại, BE tự fallback theo mặt chữ |
| `items[].reading` | `string` | — | Tối đa `120` ký tự. Tách được nhiều cách đọc cách nhau bằng khoảng trắng (`"ささえる つかえる"`), tự quy đổi Hiragana↔Katakana |
| `items[].phonetic` | `string` | — | Tối đa `120` ký tự. Alias cho `reading` (tương thích thẳng cột `Phonetic` của Mazii) |
| `items[].mean` | `string` | — | Tối đa `1000` ký tự. Đã whitelist cho cột `Mean` của Mazii (BE bỏ qua và dùng nghĩa sạch của từ điển Langoo) |
| `items[].note` | `string` | — | Tối đa `500` ký tự |
| `items[].source_type` | `string` | — | Tối đa `30` ký tự (`word` \| `kanji` \| `grammar` \| `sentence`). Khác `word` sẽ vào `not_found` (`unsupported_type`) |
| `items[].type` | `string` | — | Tối đa `30` ký tự. Alias cho `source_type` (tương thích thẳng cột `Type` của Mazii) |
| `status` | `string` | — | `'learning'` (mặc định) \| `'paused'` \| `'known'` |

> **Lưu ý `forbidNonWhitelisted`:** BE bật `ValidationPipe({ forbidNonWhitelisted: true })`. FE **chỉ gửi các field nằm trong bảng trên**, không gửi thêm cột lạ từ Excel (ví dụ `STT`, `Date`, `Level`…) để tránh `400 VALIDATION_FAILED`.

### 2.5. Mã lỗi cần xử lý trên FE

| HTTP | Error `code` | Cách xử lý trên UI |
| :---: | :--- | :--- |
| `422` | `IMPORT_NO_MATCHED_ITEMS` | **Chỉ có ở `POST /v1/collections/import`**. Không báo lỗi hệ thống chung chung — đọc `error.details.not_found` và hiện ngay màn kết quả: *"Không tạo được bộ vì không có từ nào khớp trong từ điển"* + liệt kê danh sách `not_found` |
| `400` | `VALIDATION_FAILED` | Kiểm tra lại giới hạn 1–500 dòng, `name` 1–80 ký tự, `word` 1–120 ký tự, không gửi field lạ |
| `404` | `COLLECTION_NOT_FOUND` | Sổ đích đã bị xóa/archive → báo lỗi và làm mới danh sách sổ |
| `404` | `PROFILE_NOT_FOUND` | Hồ sơ không hợp lệ → yêu cầu chọn lại hồ sơ |
| `409` | `PROFILE_REQUIRED` | User chưa có hồ sơ học → điều hướng tạo hồ sơ |
| `409` | `COLLECTION_POSITION_LIMIT_REACHED` | Bộ sưu tập đã đầy giới hạn vị trí |

## 4. Parse File & Dán nhanh ở phía FE (`src/lib/import-list-parser.ts`)

Hiện `LanGoo-User/package.json` **chưa có** thư viện đọc Excel/CSV. Đội FE cần cài thêm:
- **Đọc `.xlsx`:** `read-excel-file` (nhẹ, bảo mật tốt, không bundle nặng) hoặc `xlsx` (SheetJS).
- **Đọc `.csv`/`.tsv`:** `papaparse` (+ `@types/papaparse`) hoặc parser nhẹ hỗ trợ UTF-8 BOM & Shift-JIS (file CSV xuất từ Excel Windows tiếng Nhật hay dùng `shift-jis`, có thể decode bằng `new TextDecoder("utf-8", { fatal: true })` rồi fallback `new TextDecoder("shift-jis")`!).

### 4.1. Nhận diện & ánh xạ cột tự động

1. **File Mazii (`.xlsx` / `.csv`):**
   - Header chuẩn đã kiểm chứng từ file thật: `Word | Phonetic | Mean | Note | Type`.
   - **Tự gợi ý tên bộ mới (`suggestedName`):**
     - Ưu tiên **tên Sheet đầu tiên** trong `.xlsx` (ví dụ `Kanji Shit`) nếu không phải tên mặc định (`Sheet1`, `Trang tính1`).
     - Fallback tên file: bỏ đuôi `.xlsx/.csv`, bỏ tiền tố `Mazii_` và hậu tố timestamp `_YYYY-MM-DD_HH_MM_SS`, cắt gọn ≤ 80 ký tự.
   - Map cột:
     - `Word` → `word`
     - `Phonetic` → `phonetic`
     - `Note` → `note`
     - `Type` → `type`
     - *(Không cần gửi `Mean` để giảm dung lượng payload, hoặc gửi vào `mean` cũng hợp lệ)*.

2. **File Excel / CSV / TSV tự do:**
   Chuẩn hóa tên cột header bằng `header.trim().toLowerCase()`:
   - `word`: `word`, `từ`, `tu`, `từ vựng`, `tu vung`, `term`, `vocab`, `vocabulary`, `kanji`
   - `pos`: `pos`, `từ loại`, `tu loai`, `loại từ`, `loai tu`, `part of speech`, `word type`
   - `reading`: `reading`, `phonetic`, `phiên âm`, `phien am`, `furigana`, `kana`, `hiragana`
   - `note`: `note`, `ghi chú`, `ghi chu`, `memo`
   - `source_type`: `type`, `source_type`, `loại`, `loai`
   - Nếu file **không có dòng header** (dòng 1 không khớp bất kỳ tên cột nào ở trên): coi cột 1 là `word`, cột 2 (nếu có) là `pos`.

3. **Tab "Dán danh sách" (Paste text):**
   - Tách từng dòng theo `/\r?\n/`, bỏ dòng trắng.
   - Hỗ trợ:
     - **Mỗi dòng 1 từ:** `性質`, `bank`, `性質（せいしつ）`, `bank (n)` → gửi thẳng nguyên chuỗi vào `word` (BE tự tách ngoặc!).
     - **2 cột cách nhau bằng Tab (`\t`) hoặc `|` hoặc `,`:** cột 1 → `word`, cột 2 → `pos` (hoặc `reading` nếu cột 2 chỉ gồm Hiragana/Katakana).

### 4.2. Tiền lọc an toàn ở FE trước khi gọi API (Tránh lỗi `400` cả lô)

Trước khi gửi mảng `items` lên BE, FE nên làm sạch từng dòng:
1. Bỏ các dòng `word` rỗng / chỉ chứa khoảng trắng.
2. Cắt độ dài các field tùy chọn để không vượt trần DTO:
   - `pos`: `.slice(0, 40)`
   - `reading` / `phonetic`: `.slice(0, 120)`
   - `note`: `.slice(0, 500)`
   - `source_type` / `type`: `.slice(0, 30)`
   - Không gửi field nếu giá trị rỗng (`undefined` thay vì `""`).
3. **Nếu `word.trim().length > 120`** (ví dụ file Mazii có lẫn 1 câu văn rất dài):
   - **Không** đưa vào payload gửi BE (kẻo bị `400 VALIDATION_FAILED` hỏng cả lô).
   - Tự giữ ở FE và gộp vào danh sách báo cáo `not_found` cuối cùng với `reason: "not_in_dictionary"` (hoặc nhãn *"Quá 120 ký tự"*).

## 5. Xử lý file lớn hơn 500 dòng (Chia lô tuần tự)

Giới hạn BE là **500 dòng/request**. FE tách `items` thành các chunk `500` phần tử và gửi **tuần tự (sequential)** — không gửi song song — để giữ đúng thứ tự `position` và hiển thị thanh tiến độ (`Đang nhập 500 / 1.250 từ...`):

1. **Chế độ "Thêm vào bộ có sẵn":**
   - Lặp từng chunk gọi `importItemsIntoCollection(collectionId, { items: chunk, status })`.
2. **Chế độ "Tạo bộ mới":**
   - Khởi tạo `createdCollectionId: string | null = null`.
   - Với mỗi chunk:
     - Nếu `createdCollectionId === null`: gọi `createCollectionAndImport({ name, description, profile_id, status, items: chunk })`.
       - Thành công → lưu `createdCollectionId = res.collection.id`, cộng dồn kết quả.
       - Nếu nhận `422 IMPORT_NO_MATCHED_ITEMS` → lấy `error.details.not_found` cộng dồn vào mảng `notFound` (chưa dừng nếu còn chunk sau!).
     - Nếu `createdCollectionId !== null`: gọi `importItemsIntoCollection(createdCollectionId, { items: chunk, status })`, cộng dồn kết quả.
   - Sau khi chạy hết tất cả các chunk: nếu `createdCollectionId === null` (toàn bộ file 0 từ khớp) → hiện màn tổng kết báo không tạo được bộ + danh sách `notFound` đầy đủ.
3. **Cộng dồn kết quả:**
   - Cộng `total_submitted`, `added_count`, `skipped_duplicate_count`, `not_found_count`.
   - Điều chỉnh `index` hiển thị thành số dòng thực tế trong file (`chunkOffset + item.index + 1`).

## 6. Làm mới Cache (`TanStack Query` trong `src/hooks/use-collections.ts`)

Sau khi import kết thúc (nếu có tạo bộ mới hoặc `added_count > 0`), gọi đúng các hàm invalidate hiện có trong `src/hooks/use-collections.ts`:

```ts
void queryClient.invalidateQueries({ queryKey: collectionKeys.list })
if (targetCollectionId) {
  void queryClient.invalidateQueries({ queryKey: collectionKeys.detail(targetCollectionId) })
  void queryClient.invalidateQueries({ queryKey: ["collections", targetCollectionId, "items"] })
}
invalidateStudyData(queryClient)
```

> Lưu ý: `useSavedSense` dùng key `["collections", "saved-senses", ...]`, nằm dưới tiền tố `collectionKeys.list` (`["collections"]`), nên `invalidateQueries({ queryKey: collectionKeys.list })` sẽ **tự động làm mới luôn trạng thái đã lưu ở màn tra từ điển** (đúng contract M12-A18).

## 7. Hướng dẫn UI/UX & i18n

### 7.1. Bố cục Dialog `ImportListDialog.tsx`
1. **Bước nhập liệu (Form):**
   - **Chọn đích đến** (Radio / Tabs):
     - `Thêm vào bộ có sẵn` → Select danh sách collection từ `useCollectionsQuery()` (chỉ hiển thị bộ của hồ sơ đang active).
     - `Tạo bộ mới` → Ô nhập Tên bộ (`maxLength={80}`, bắt buộc) + Mô tả tùy chọn.
   - **Chọn nguồn dữ liệu** (Tabs):
     - `Tải file (.xlsx, .csv, .tsv)` → vùng kéo thả / chọn file + dòng tóm tắt ngay sau khi đọc xong: *"Đã đọc **10 từ** từ file `Mazii_Kanji Shit...xlsx`"* (kèm cảnh báo nhỏ nếu có dòng bị tiền lọc do > 120 ký tự).
     - `Dán danh sách` → Textarea nhiều dòng kèm placeholder ví dụ:
       ```text
       性質
       支える（ささえる）
       bank (n)
       go, verb
       ```
   - **Tùy chọn trạng thái học (gọn, có thể để mặc định):**
     - `Học mới (mặc định)` (`learning` — tự dàn theo giới hạn từ mới/ngày của SRS)
     - `Đã thuộc (chỉ lưu tra cứu)` (`known`)
   - Nút chính: **"Nhập X từ"** (disable khi đang gửi hoặc `parsedItems.length === 0`, hoặc thiếu tên bộ / chưa chọn bộ).
2. **Màn Tổng kết kết quả (sau khi API trả về):**
   - **Khối tóm tắt 3 chỉ số:**
     - Xanh lá: `Đã thêm: X từ`
