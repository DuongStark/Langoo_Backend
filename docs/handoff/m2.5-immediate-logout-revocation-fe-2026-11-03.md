# M2.5 — Thu hồi access token ngay khi đăng xuất — Handoff FE

Ngày: 2026-11-03. Backend giữ nguyên URL và response logout; thay đổi hiệu lực token.
[Plan](../plans/m2.5-immediate-logout-revocation-2026-11-03.md) · [API auth](../api/auth.md).

## Contract và tác động

`POST /v1/auth/logout`, header `Authorization: Bearer <access_token>`, không cần body.
Thành công `200 { "id": "<session UUID>", "revoked_at": "<ISO timestamp>" }`.

- Sau 200, access token cũ/mới và refresh token của cùng session không còn dùng được
  trên request mới. Token bị sao chép trước khi logout cũng bị chặn.
- Chỉ session đang logout bị thu hồi. Phiên đăng nhập trên thiết bị/trình duyệt khác vẫn hoạt động.
- Backend giữ row session bị revoke để retry/audit; không có API xóa vật lý JWT.
- Logout retry bằng JWT chưa hết hạn trả cùng kết quả 200. JWT hết hạn vẫn 401.
- API cần auth, admin và API optional auth đều kiểm session. Optional auth không
  header vẫn cho guest; header đã revoke trả 401, không tự bỏ qua để vào chế độ guest.
- Session hết hạn, bị xóa, sai owner, user locked/deleted cũng trả 401 `AUTH_TOKEN_INVALID`.
- Lỗi truy vấn session ở guard trả 503 `AUTH_SERVICE_UNAVAILABLE`, không phải yêu cầu đăng nhập lại.
- Request/stream đã qua guard trước logout có thể tiếp tục; không có push revoke tới browser.

## Việc FE cần làm

1. Khóa nút logout trong lúc xử lý; dừng tạo request cần auth mới, dừng vòng refresh
   tự động. Chỉ dùng một luồng refresh/logout của auth store để tránh race UI.
2. Abort chat SSE, quiz stream và request đang chạy; bỏ qua callback muộn bằng
   auth-generation/session-generation của store để response cũ không nạp lại dữ liệu.
3. Nếu access token đã hết hạn và refresh token còn dùng được, refresh một lần rồi
   gọi logout bằng token mới. Không retry refresh vô hạn. Refresh bị từ chối do
   session hết hạn/đã revoke thì xóa local và về màn đăng nhập.
4. Gọi logout và chờ response. Khi 200: xóa access/refresh token ở nơi FE thực sự
   đang lưu (storage/memory/cookie thuộc FE), auth store, user cache và dữ liệu riêng
   của người dùng trong query cache; điều hướng về trạng thái chưa đăng nhập.
5. Đồng bộ logout giữa các tab cùng session bằng cơ chế sẵn có hoặc BroadcastChannel;
   tab khác abort stream/clear state. Không xóa session trên thiết bị khác qua backend.
6. Với network error/5xx: coi kết quả server là chưa xác nhận, cho retry logout.
   Không tự hiểu local cleanup là token server đã bị revoke. Nếu UX cho rời tài khoản
   ngay, vẫn xóa dữ liệu riêng local và nói rõ chưa xác nhận đăng xuất phía server;
   không lưu token vào log/URL hoặc tạo hàng đợi retry bền vững không được bảo vệ.
7. Với 401 trên API thường: auth interceptor chỉ thử refresh một lần; refresh 401
   thì clear session. Chặn recursion ở auth endpoints. Sau logout chủ động, không
   khởi động lại refresh. Với 503 `AUTH_SERVICE_UNAVAILABLE`: hiển thị lỗi tạm thời,
   giữ trạng thái credential để retry, không tự xóa tài khoản/cache như xử lý 401.

Không cần đổi payload/API path hoặc migration FE data. Nếu FE đã có chuỗi logout→clear
thì rà bước await, stream, callback muộn, 503 và nhiều tab. Chưa sửa source Langoo_User
trong hạng mục này. OpenAPI đang có tên SessionResponseDto trùng (M12-A06); tham chiếu
contract logout ở trên, không tự sinh lại toàn client trước khi sửa finding đó.

## Checklist QA FE

- [ ] Đăng nhập → sao chép access token A → logout 200 → dùng A GET `/v1/auth/me` nhận 401.
- [ ] Refresh A trước logout → cả access cũ và mới đều 401 sau logout; refresh mới cũng 401.
- [ ] Session B trên trình duyệt khác vẫn GET me 200 sau khi logout A.
- [ ] Retry logout cùng JWT chưa hết hạn trả 200 và không đổi revoked_at.
- [ ] Tab đang chat không hiển thị tin đến muộn sau logout; không lưu lại user cache.
- [ ] Dictionary public mở lại được khi không còn Authorization header cũ.
- [ ] DB/auth service 503 không kích hoạt vòng refresh/logout hoặc redirect liên tục.
- [ ] Mất mạng lúc logout hiển thị trạng thái chưa xác nhận; không báo đã thu hồi server.
