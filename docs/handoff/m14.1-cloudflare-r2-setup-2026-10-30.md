# M14.1 — Lưu ảnh Muse trên R2 và liên kết concept

Ngày 2026-10-30. Chủ dự án chốt prompt C và yêu cầu bước lưu Cloudflare → gắn concept;
sau kiểm tra xác nhận chưa tạo R2, cần hướng dẫn thiết lập.

## 1. Tạo bucket và domain ảnh

1. Đăng nhập [Cloudflare Dashboard](https://dash.cloudflare.com/) bằng tài khoản đang quản lý
   zone `langoo.org`.
2. Mở **Storage & databases → R2 Object Storage → Overview**. Nếu chưa kích hoạt, hoàn tất
   bước đăng ký R2 theo dashboard. Cloudflare có thể yêu cầu thông tin thanh toán để kích hoạt;
   người dùng tự hoàn tất bước tài khoản này. Chọn **Standard storage** cho bucket.
3. Chọn **Create bucket**, tên đề xuất `langoo-image`; location để Automatic,
   không chọn jurisdiction đặc biệt nếu không có yêu cầu riêng. Tạo bucket.
4. Vào bucket → **Settings → Custom Domains → Add**, nhập `media.langoo.org`, rồi
   **Continue → Connect Domain**. Đợi trạng thái **Active**. Bucket và zone cần cùng account.
   Domain này dùng cho ảnh minh họa được phép công khai; không đưa feedback/secret/manifest private vào bucket.
5. Không cần bật `r2.dev` khi đã dùng custom domain. `r2.dev` dành cho phát triển,
   còn custom domain hỗ trợ cache của Cloudflare.

Nguồn chính thức: [R2 S3 setup](https://developers.cloudflare.com/r2/get-started/s3/),
[Public buckets và custom domains](https://developers.cloudflare.com/r2/buckets/public-buckets/).

## 2. Tạo khóa đúng loại cho R2

1. Trở lại **R2 → Overview** → phần **API Tokens → Manage**.
2. Chọn **Create Account API token** (hoặc User API token nếu tài khoản không có lựa chọn Account).
3. Permission: **Object Read & Write**.
4. Scope: **Apply to specific buckets only** → chọn `langoo-image`.
5. Tạo token. Lưu đúng **Access Key ID** và **Secret Access Key** vào file local ở mục 3.
   Secret chỉ hiện lúc tạo; không gửi qua chat, không đưa vào repo tracked hoặc screenshot công khai.
   Đây là credentials S3 của R2; không thay bằng Bearer token của API Cloudflare thông thường.
6. Lấy **Account ID** từ Overview/Account Details, hoặc hostname S3 endpoint:
   `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

Nguồn: [R2 Authentication](https://developers.cloudflare.com/r2/api/tokens/).
Object Read & Write chỉ cấp thao tác object cho bucket đã chọn; setup domain/bucket ở dashboard
do chủ tài khoản thực hiện, không cấp thêm quyền quản trị Cloudflare cho job upload.

## 3. Điền file local, không gửi secret vào chat

File ngoài repo: `~/.config/langoo/r2.env`, mode 0600, parent directory 0700.
Ổ repo không áp dụng được chmod 0600 (thực tế vẫn 0777), nên không lưu secret tại đó.
Template trống ban đầu trong repo đã được gỡ sau khi đối chiếu đúng nội dung do phiên này tạo.
Các tên bucket/domain là đề xuất cấu hình, có thể đổi cho khớp tài khoản thực:

```dotenv
R2_ACCOUNT_ID=
R2_BUCKET=langoo-image
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_PUBLIC_BASE_URL=https://media.langoo.org
```

Điền ba giá trị trống trực tiếp bằng editor local, lưu file rồi báo “đã cấu hình R2”.
Không paste nội dung file vào chat. File này chưa được app hiện tại nạp, không thay `.env` production
hoặc `STORAGE_PROVIDER` của feedback. Chưa sao chép khóa lên VPS.

## 5. Thiết kế đã thực hiện

**Thiết kế đã chốt:** công cụ vận hành upload trước, DB metadata sau; bucket ảnh riêng,
không chuyển storage feedback riêng tư sang public bucket.

1. Giữ prompt C có version. Manifest lấy `sense_id` từ dữ liệu gốc và mapping DB, không lấy IDs
   trong lời trả lời Muse (lô 2 đã bắt được hoán đổi IDs).
2. Upload ảnh đã kiểm sang R2 qua S3 API, object key theo hash, không ghi đè key nội dung khác.
   Kiểm MIME/kích thước/hash và GET đọc lại thành công trước khi ghi liên kết DB.
3. DB chỉ lưu object key, hash, metadata nguồn/prompt và FK ảnh–concept; không lưu blob hoặc URL
   Muse/blob URL/presigned URL sẽ hết hạn. URL public dựng từ base domain cấu hình + object key.
4. Migration SQL mới 045: mở rộng media kind và thêm bảng
   nối concept–asset, provenance nguồn nghĩa, trạng thái duyệt, một ảnh primary cho mỗi concept.
   Không sửa migration cũ; không map `core` vào Prisma hoặc chạy Prisma migrate/db push.
5. Job dry-run mặc định, idempotent theo hash/mapping, journal từng bước. DB transaction chỉ sau
   upload xác minh; lỗi DB giữ object trong journal để reconcile, không gán dữ liệu sai hoặc upload lại mù.
6. Concept draft/thiếu mapping giữ pending. Pilot đầu có thể xác minh upload/gắn `picnic`;
   phần thiếu mapping phải đi qua quy trình mapping/curation hiện có.
7. Khi làm API đọc ảnh, chỉ trả asset đủ điều kiện và concept curated; bàn giao contract cho FE.
   Chưa có API consumer mới trong lượt setup này.
