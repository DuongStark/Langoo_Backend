## 1. Trả lời 4 câu hỏi §4 của FE

1. **`word` có thể bỏ bắt buộc khi có `jmdict_id` không?**
   - **Đã mở:** `word` trở thành tùy chọn khi có `jmdict_id`. FE chỉ cần gửi `{ jmdict_id: "1355120" }` (không cần gửi `word` giả).
   - Bắt buộc có **ít nhất 1** trong `word` hoặc `jmdict_id` (gửi `{}` trả `400 VALIDATION_FAILED`).
   - Nếu gửi cả hai thì **ưu tiên `jmdict_id`**; `word` chỉ dùng làm nhãn hiển thị nếu rơi vào `not_found`.
2. **Reason khi không tìm thấy mã JMdict:**
   - **Đã thêm enum `jmdict_not_found`** vào `ImportNotFoundItemDto.reason` (`not_in_dictionary | language_not_in_profile | unsupported_type | jmdict_not_found`).
   - Nếu mã tồn tại trong JMdict nhưng hồ sơ học của user không bật tiếng Nhật (vd hồ sơ EN-only) → trả **`language_not_in_profile`** (kèm `word = lemma` để FE hiển thị thân thiện).
3. **581 chữ Hán đơn (`体`, `髪`, `発`…):**
   - Tầng từ điển `core.kanji` có đủ 13.108 chữ Hán, nhưng tầng sổ tay `app.collection_item` hiện chỉ lưu từ vựng (`core.sense`), chưa có bảng riêng cho "Thẻ học Kanji".
   - Giữ `source_type: "kanji"` là `unsupported_type` như hiện tại. Với file `.japanese`, FE **cứ gửi 581 chữ Hán đơn qua `word`** (không kèm `source_type`): chữ nào có mục từ trong từ điển sẽ được lưu như từ vựng thường (mở chi tiết vẫn có phân tích Kanji), chữ nào không tồn tại độc lập sẽ vào `not_found`.
4. **`external_id` đã có index chưa? Có cần cột/migration mới không?**
   - Đã xác minh trên DB production: `core.lexeme(external_id)` **đã có sẵn `UNIQUE B-TREE INDEX` (`lexeme_external_id_key`)** với đúng định dạng `jmdict:<ent_seq>` (`jmdict:1355120` → `乗る`, `jmdict:1589500` → `降りる`…).
   - BE tra cả lô 500 mã bằng **1 câu SQL duy nhất** `WHERE l.external_id = ANY($externalIds::text[])` — chạy trong vài mili-giây, **0 migration DB**.

## 2. Hợp đồng API cập nhật (`POST /v1/collections/import` & `POST /v1/collections/:id/items/import`)

### Request (`ImportItemInputDto`)

```ts
export interface ImportItemInputDto {
  word?: string        // bắt buộc nếu không có jmdict_id (1..120 ký tự)
  jmdict_id?: string   // 1..10 chữ số (/^\d{1,10}$/), vd "1355120"
  pos?: string
  reading?: string
  phonetic?: string
  mean?: string
  note?: string
  source_type?: string
  type?: string
}
```

Ví dụ gửi từ file backup `.japanese`:
```json
{
  "name": "16+Kanji11",
  "items": [
    { "jmdict_id": "1355120", "note": "ghi chú nếu có" },
    { "jmdict_id": "1589500" },
    { "word": "髪", "note": "PHÁT" }
  ]
}
```

### Response

Cấu trúc giữ nguyên, hành vi cụ thể cho item dùng `jmdict_id`:
- **`added[]`:** `word` trả **`lemma`** (vd `"乗る"`) để màn tổng kết FE hiển thị được mặt chữ; `deinflected_from: null`.
- **`skipped_duplicates[]`:** `word` trả **`lemma`** (hoặc `word` nếu FE có gửi).
- **`not_found[]`:** `reason` là `"jmdict_not_found"` (hoặc `"language_not_in_profile"` nếu hồ sơ không học tiếng Nhật); `word` trả `word` nếu FE gửi, không thì trả `"jmdict:<id>"` (vd `"jmdict:9999999"`).

## 3. Việc FE cần cập nhật (sau khi BE deploy)

1. Cập nhật `src/types/api.ts`:
   - `ImportItemInputDto`: đổi `word?: string`, thêm `jmdict_id?: string`.
   - `ImportNotFoundReason`: thêm `"jmdict_not_found"`.
2. Cập nhật nhãn i18n cho `jmdict_not_found`:
   - VI: *"Mã từ điển JMdict không có trong từ điển Langoo"* (hoặc *"Không có trong từ điển Langoo"*).
   - EN: *"JMdict entry not found in Langoo dictionary"*.
3. Trong parser file `.japanese` (GZIP `1F 8B` → JSON `lists[].entries[].ref`):
   - `ref` trong `0x3400..0x9FFF` → `{ word: String.fromCodePoint(ref), note }` (không gắn `source_type`).
   - `ref >= 1_000_000` → `{ jmdict_id: String(ref), note }`.
   - Gửi qua 2 API `M5.3` hiện tại (chia lô 500, tuần tự).
