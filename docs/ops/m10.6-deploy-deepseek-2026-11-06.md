AI_API_KEY và AI_QUIZ_API_KEY = Secret Key Deploy trong server .env; Access Key ID
chỉ dùng quản lý, không phải bearer. Không ghi secret vào command args, log, shell
history, chat đáp lại hoặc report. Giữ AI_CHAT_MAX_TOKENS4000 hiện tại, timeout,
quota/cooldown, rate-limit, consent/enforcement và các ENV không liên quan.

## Trình tự

1. Preflight git HEAD/working tree, Node, process/PM2 ENV đã lọc AI secret, health.
   Hiện PM2 không inject AI_* nên runtime sẽ đọc .env mới sau reload; nếu có injected
   override phải xử lý rõ nguồn, không log pm2 jlist nguyên bản.
2. Review/test code none xong, chỉ rollout phạm vi được chủ dự án cho phép. Không
   push/deploy code ngoài yêu cầu. Không DB migration cho M10.6.
3. Backup .env ngoài repo vào thư mục chỉ service owner đọc được, mode600; không
   sao chép secret sang uploads hoặc docs. Snapshot có cả khóa cũ phục vụ rollback.
4. Tạo candidate .env bằng update đúng key ở trên + hai Secret Key; không replace
   toàn file bằng ENV mẫu, xử lý duplicate key rõ, validateEnv với config mới.
   Chỉ đặt none sau khi build mới hỗ trợ none đã sẵn sàng; update atomic, owner đúng,
   mode600. Không vô tình inject key cũ từ dotenv-loaded process vào PM2 update-env.
5. Build/reload service có kiểm soát, health/manifest HTTP200; xác minh model/effort
   mới bằng process diagnostic đã che key và fixture provider trên server qua factory
   thật. Không mint token user/POST consent thật để smoke. Test stream có delta,
   JSON quiz parse đúng, ảnh giả hỗ trợ và reasoning usage0 nếu có field usage.
6. Failure: restore backup atomic, reload old working profile, xác minh health;
   giữ log chỉ metadata đã redacted. Không tự fallback Groq cho từng request nếu
   không có thiết kế/đồng ý riêng về vendor hoặc quota.
