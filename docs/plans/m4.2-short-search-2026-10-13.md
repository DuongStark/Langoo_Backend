# M4.2 — Tối ưu search một ký tự

Ngày 2026-10-13. Chủ dự án yêu cầu tối ưu sau [khảo sát VPS](../reviews/m4.2-single-character-search-2026-10-13.md).

## Thiết kế

- Một ký tự Latin ASCII: tìm prefix trên mặt chữ/reading/romaji, giữ exact ở đầu. Đây là lựa chọn triển khai: gõ `a` không còn trả `cat` chỉ vì chứa `a`; gõ từ >=2 ký tự vẫn substring như trước. Escape LIKE và query variants vẫn được giữ.
- Một ký tự khác, bao gồm Kanji/kana: giữ substring; bổ sung hàm `core.search_characters` trả các ký tự Unicode riêng biệt và 4 GIN expression index. Không sửa hàm bigram/index cũ đang hoạt động.
- Bổ sung 4 B-tree expression index `lower(...) text_pattern_ops` để prefix/equality dùng được cả trên view lemma/form. Migration mới 042, vì VPS đã có 041 của workstream khác.
- Nhánh reading/romanization vẫn giữ theo schema thực, không giả định EN luôn NULL. Query filter chọn toán tử phù hợp từng variant theo số code point Unicode, không theo số âm tiết/UTF-16 code unit.
- Giữ source visibility, ranking, dedup, language scope và cursor hiện có; không thêm LIMIT ứng viên tùy ý.
- Một ký tự: lấy exact tier trước bằng B-tree; chỉ trả ngay nếu đủ `limit` (search truyền LIMIT+1). Nếu chưa đủ, chạy full query để giữ trang/cursor. Cursor đã ở tier non-exact bỏ qua bước này. Visibility exact tier kiểm tra canonical JMdict trên **toàn bộ** match policy để không làm hiện lại nguồn bị ẩn.
- Suggestion một chữ ASCII và scope EN riêng: sau exact tier, thử pool gồm **mọi exact match** và prefix có `frequency_rank <= 10000`. Nếu pool đã đủ kết quả thì phần bị bỏ tạm đều là prefix tần suất thấp hơn/NULL, đứng sau trong ordering EN, nên top kết quả giống full query. Nếu chưa đủ thì fallback full query. Không áp tối ưu này cho JA, mixed scope hoặc cursor, vì source/VI priority có thể đứng trước frequency. Canonical visibility vẫn kiểm trên full match set.
- Success response giữ schema hiện có; timeout trả HTTP 504 `DICTIONARY_SEARCH_TIMEOUT`. Repo dùng transaction custom plan, statement timeout 20s và tắt JIT theo overhead đã đo. VPS có hotfix nuốt timeout; lúc tích hợp phải thay hành vi đó, không ghi đè các sửa runtime khác.

## Thực hiện và kiểm tra

1. Viết integration regression trên DB test riêng: prefix Latin không match giữa từ; Kanji match đầu/cuối; Unicode ngoài BMP; literal wildcard; language scope; cursor không mất/lặp lexeme với nhiều face.
2. Chạy test đỏ trước khi đổi query, rồi thêm migration/query và chạy xanh.
3. Chạy unit toàn dự án, e2e dictionary liên quan, build/lint phù hợp.
4. Đo bằng repository trên local full, ghi số liệu trước/sau và số index. Không gọi số liệu local là latency VPS.
5. Lưu docs/API/PROGRESS và checklist deploy: migration trước code; tích hợp predicate vào runtime VPS thay vì thay toàn file, xác minh ranking/translation hotfix; smoke lại API.
