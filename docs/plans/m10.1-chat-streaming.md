# Kế hoạch M10.1 — Chat streaming & chịu lỗi

> Trạng thái: **đang triển khai** (chủ dự án chốt 05/10 sau khi chat bị 503/chậm với Zen free).
> Mục tiêu: trả lời **hiện dần như ChatGPT** + hết 503 do timeout + retry khi provider quá tải.

## 1. Phạm vi

| Nhóm | Nội dung |
| --- | --- |
| A. Streaming | Provider `chatStream()` (OpenAI-compatible SSE), service phát sự kiện, endpoint `POST /v1/chat/sessions/:id/messages/stream` (`text/event-stream`): `start` → `delta`* → `done`/`error` |
| B. Chịu lỗi | Retry 1 lần khi 429/5xx/timeout (chỉ khi chưa phát delta); lỗi provider giữa stream → event `error`; hủy upstream khi client ngắt kết nối |
| C. Cấu hình | `AI_CHAT_TIMEOUT_MS` (mặc định 60s — thay hardcode 30s), `AI_CHAT_MAX_TOKENS`, `AI_CHAT_REASONING_EFFORT` (cho model suy luận) |
| D. Giữ nguyên | Endpoint cũ `POST .../messages` không đổi (fallback khi FE chưa lên streaming); quota/lease/persist dùng chung |

## 2. Quyết định

- **D1** — SSE qua `POST` + `@Res()` (không dùng `EventSource` vì cần header Authorization + body).
- **D2** — Chỉ ghi DB khi stream **thành công** (giống endpoint cũ: provider lỗi không lưu tin; quota đã reserve vẫn tính).
- **D3** — `error` event chỉ dùng khi đã phát delta; lỗi sớm (busy/archived/quota/provider fail trước delta) trả JSON status như cũ.
- **D4** — Không thêm dependency; tự parse SSE (`data:` lines, `[DONE]`, bỏ `reasoning_content`).
- **D5** — Model reasoning: stream chỉ phát `delta.content`; nội dung rỗng sau stream → coi là lỗi.

## 3. Hợp đồng sự kiện (FE đọc)

```
event: start   data: {"model":"openai/gpt-oss-120b"}
event: delta   data: {"content":"Xin "}
event: delta   data: {"content":"chào"}
event: done    data: { user_message, assistant_message, usage }   // như endpoint cũ
event: error   data: {"code":"AI_PROVIDER_UNAVAILABLE","message":"..."}
```
FE dùng `fetch(..., { method:'POST', headers:{Authorization}, body })` rồi đọc `response.body.getReader()`.

## 4. Tiêu chí nghiệm thu

- [ ] `POST .../messages/stream` trả `text/event-stream`, delta chảy dần (kiểm chứng bằng curl `-N` với Groq thật)
- [ ] Endpoint cũ không đổi hành vi; e2e cũ vẫn xanh
- [ ] Unit: parse SSE (chunk cắt giữa dòng, `[DONE]`, bỏ reasoning, lỗi 429 → retryable), stub stream
- [ ] E2E mới: stream lưu đủ 2 tin nhắn sau `done`
- [ ] VPS: `.env` thêm timeout/effort; chat trả chữ dần, không 503 khi provider chậm vừa phải
