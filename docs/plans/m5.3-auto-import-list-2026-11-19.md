## 1. Bối cảnh & Quyết định sản phẩm đã chốt

1. **Luồng 1 bước tự động hoàn toàn (Auto-Import):**
   - Người dùng đưa danh sách từ (upload file Mazii `.xlsx`/`.csv`, Excel/CSV/TSV hoặc copy-paste danh sách) → chọn **nhập vào bộ có sẵn** hoặc **tạo bộ mới** → hệ thống tự đối chiếu theo **mặt chữ + từ loại** (có hỗ trợ thêm phiên âm `reading` nếu file có như Mazii) → **tự chọn 1 nghĩa phổ biến nhất** theo bộ xếp hạng M10.5 / M4.5 → **tự ghi thẳng vào sổ tay**.
   - **Không** bắt người dùng dừng lại chọn từng nghĩa thủ công.
   - Từ nào không khớp được trong từ điển (hoặc khác ngôn ngữ hồ sơ / không phải loại từ vựng) → **trả rõ danh sách `not_found`** để FE thông báo ngay cho người dùng.
2. **Xử lý khi lệch từ loại (`pos`):**
   - Nếu người dùng có gửi từ loại (`pos`) và trong từ điển có mục từ khớp đúng `(mặt chữ + pos)` → **ưu tiên chọn tuyệt đối**.
   - Nếu trong từ điển có mặt chữ đó nhưng không có đúng `pos` gửi lên (thường gặp do khác cách phân loại giữa các nguồn, ví dụ tính từ đuôi な hay danh từ tiếng Nhật) → **fallback sang mục từ khớp mặt chữ tốt nhất** để tránh mất từ oan.
3. **Giữ nguyên các bất biến kiến trúc của Langoo:**
   - **0 migration DB**, **0 package npm mới** ở backend.
   - **Tuyệt đối không** ghi dữ liệu người dùng vào `core.lexeme` / `core.sense` (không tạo "custom sense" trong schema `core`).
   - Toàn bộ từ nhập vào đều neo vào `core.sense` hợp lệ → dùng trọn vẹn Flashcard, SRS recognize-only (M6.3), hiển thị nghĩa + Kanji (M12-A19), ảnh minh họa (M14) và Ngân hàng Quiz (M11.5).
   - Nghĩa tiếng Việt lưu vào `collection_item.meaning_vi` lấy mặc định từ từ điển sạch của Langoo (`gloss_vi` → fallback `gloss_en` → `lemma`, cùng công thức với `DeckRepository.findItems`).
   - Không cần xây logic giãn lịch SRS riêng vì `app.user_settings.srs_new_per_day` (mặc định 20 từ mới/ngày) đã tự điều tiết số thẻ `state = 'new'` mỗi ngày.

## 2. Đặc tả API Contract (Swagger & REST)

Cả hai endpoint đều yêu cầu **Bearer JWT (`JwtAuthGuard`)** và tôn trọng phạm vi ngôn ngữ của `study_profile` (`primary_language_id`, `secondary_language_id`).

### 2.1. Endpoint 1 — Nhập danh sách vào bộ sưu tập có sẵn

- **Route:** `POST /v1/collections/:collectionId/items/import`
- **HTTP Status thành công:** `201 Created` (kể cả khi `added_count = 0` do toàn trùng hoặc toàn không tìm thấy — tương đồng hành vi `POST /v1/collections/:id/from-deck`).
- **Request Body (`ImportItemsDto`):**

```json
{
  "items": [
    {
      "word": "支える",
      "pos": "verb",
      "reading": "ささえる つかえる",
      "note": "gặp trong N2",
      "source_type": "word"
    },
    {
      "word": "bank",
      "pos": "n"
    },
    {
      "word": "性質"
    }
  ],
  "status": "learning"
}
```

| Field | Kiểu | Bắt buộc | Quy tắc validation |
| :--- | :--- | :---: | :--- |
| `items` | `ImportItemInputDto[]` | ✅ | Mảng `1..500` phần tử (`ArrayMinSize(1)`, `ArrayMaxSize(500)`) |
| `items[].word` | `string` | ✅ | Trim + chuẩn hóa NFKC, `1..120` ký tự |
| `items[].pos` | `string` | — | Trim, tối đa `40` ký tự; backend tự chuẩn hóa alias về 15 giá trị `core.lexeme.pos` |
| `items[].reading` | `string` | — | Trim + NFKC, tối đa `120` ký tự (nhận cả chuỗi nhiều cách đọc cách nhau bằng khoảng trắng như Mazii `Phonetic`) |
| `items[].note` | `string` | — | Trim, tối đa `500` ký tự; rỗng đổi thành `null` |
| `items[].source_type` | `string` | — | Trim lowercase, tối đa `30` ký tự (vd cột `Type` của Mazii: `word`, `kanji`, `grammar`, `sentence`). Không gửi mặc định coi là `word` |
| `status` | `'learning' \| 'paused' \| 'known'` | — | Mặc định `'learning'`. Cho phép import ở trạng thái `'known'` nếu user chỉ muốn lưu tra cứu |

### 2.2. Endpoint 2 — Tạo bộ sưu tập mới và nhập danh sách trong 1 bước

- **Route:** `POST /v1/collections/import`
- **HTTP Status thành công:** `201 Created`
- **Request Body (`CreateCollectionAndImportDto`):** kế thừa toàn bộ field của `ImportItemsDto` cộng thêm thông tin bộ sưu tập (giống `CreateCollectionDto`):

```json
{
  "name": "Kanji Shit",
  "description": "Import từ Mazii",
  "profile_id": "019...",
  "status": "learning",
  "items": [
    { "word": "性質", "reading": "せいしつ", "source_type": "word" }
  ]
}
```

| Field bổ sung | Kiểu | Bắt buộc | Quy tắc validation |
| :--- | :--- | :---: | :--- |
| `name` | `string` | ✅ | Trim, `1..80` ký tự (FE tự gợi ý bằng tên sheet/tên file Mazii) |
| `description` | `string` | — | Tối đa `500` ký tự |
| `profile_id` | `uuid` | — | Mặc định lấy `active_profile_id` → hồ sơ `is_default` (nếu user chưa có profile trả `409 PROFILE_REQUIRED`) |

- **Quy tắc chống tạo bộ rỗng rác:**
  - Khi gọi `POST /v1/collections/import`, nếu **0 từ nào khớp được** (`toInsert.length === 0`, tức 100% rơi vào `not_found`), server **không tạo collection trong DB** mà trả **`422 Unprocessable Entity`** với mã lỗi `IMPORT_NO_MATCHED_ITEMS` kèm `details`:
    ```json
    {
      "code": "IMPORT_NO_MATCHED_ITEMS",
      "message": "Không tìm thấy từ nào hợp lệ trong từ điển để tạo bộ sưu tập",
      "details": {
        "total_submitted": 3,
        "not_found_count": 3,
        "not_found": [
          { "index": 0, "word": "xyz123", "pos": null, "reason": "not_in_dictionary" }
        ]
      }
    }
    ```
  - Lưu ý: nếu file lớn hơn 500 từ, FE gọi `POST /v1/collections/import` cho lô đầu tiên để lấy `collection.id`, sau đó gọi `POST /v1/collections/:id/items/import` cho các lô tiếp theo.

- **Các giá trị `reason` của `skipped_duplicates`:**

### 2.4. Mã lỗi chuẩn (Error Codes)

| HTTP | Error Code | Tình huống |
| :---: | :--- | :--- |
| `400` | `VALIDATION_FAILED` | Payload sai kiểu, `items` rỗng hoặc > 500 phần tử, `word` rỗng/quá dài, UUID sai |
| `401` | `UNAUTHORIZED` | Thiếu hoặc sai Bearer token |
| `404` | `COLLECTION_NOT_FOUND` | `:collectionId` không tồn tại, đã archive, hoặc không thuộc user |

## 3. Thuật toán chuẩn hóa & đối soát tự động

### 3.1. Bước 1 — Chuẩn hóa đầu vào (`pos-normalizer.ts`)

1. **Chuẩn hóa từ (`word`):**
   - `word.normalize('NFKC').trim().replace(/\s+/g, ' ')`.
   - Sinh khóa tra cứu: `exactKey = word`, `lowerKey = word.toLowerCase()` (hỗ trợ tiếng Anh không phân biệt hoa/thường như `"Bank"` → `"bank"`, `"Apple"` → `"apple"`).
2. **Kiểm tra `source_type`:**
   - Cho phép: `undefined`, `''`, `'word'`, `'vocab'`, `'vocabulary'`, `'từ vựng'`, `'tu vung'`.
   - Các giá trị khác (`'kanji'`, `'grammar'`, `'sentence'`, `'ngữ pháp'`, `'hán tự'`, `'câu'`…) → đánh ngay vào `not_found` với `reason: 'unsupported_type'`, không truy vấn DB.
3. **Chuẩn hóa từ loại (`pos`) về 15 giá trị `core.lexeme.pos`:**
   Danh sách chuẩn đã xác minh trên DB production: `adjective`, `adverb`, `auxiliary`, `conjunction`, `counter`, `determiner`, `expression`, `interjection`, `noun`, `particle`, `prefix`, `pronoun`, `suffix`, `unknown`, `verb`.

   Bảng ánh xạ chính (không phân biệt hoa/thường, bỏ dấu ngoặc/dấu chấm như `(n.)`, `[v]`, `adj-na`):
   - `noun`: `n`, `noun`, `danh từ`, `danh tu`, `dt`, `名詞`, `n-adv`, `n-t`, `n-pref`, `n-suf`, `vs` (lưu ý: danh từ dùng với する vẫn là `noun` trong JMdict)
   - `verb`: `v`, `verb`, `vi`, `vt`, `động từ`, `dong tu`, `đt`, `動詞`, `v1`, `v5`, `v5r`, `v5u`, `v5k`, `v5s`, `v5t`, `v5m`, `v5n`, `v5b`, `v5g`, `vs-i`, `vk`
   - `adjective`: `adj`, `a`, `adjective`, `adj-i`, `adj-na`, `adj-no`, `adj-pn`, `tính từ`, `tinh tu`, `tt`, `形容詞`, `形容動詞`, `連体詞`
   - `adverb`: `adv`, `adverb`, `trạng từ`, `trang tu`, `phó từ`, `pho tu`, `副詞`
   - `pronoun`: `pron`, `pronoun`, `đại từ`, `dai tu`, `代名詞`
   - `conjunction`: `conj`, `conjunction`, `liên từ`, `lien tu`, `接続詞`
   - `interjection`: `int`, `intj`, `interjection`, `thán từ`, `than tu`, `感動詞`
   - `auxiliary`: `aux`, `aux-v`, `aux-adj`, `auxiliary`, `trợ động từ`, `助動詞`
   - `particle`: `part`, `prt`, `particle`, `trợ từ`, `tro tu`, `助詞`
   - `counter`: `ctr`, `counter`, `lượng từ`, `luong tu`, `助数詞`
   - `determiner`: `det`, `determiner`, `hạn định từ`
   - `expression`: `exp`, `expr`, `expression`, `phrase`, `idiom`, `cụm từ`, `thành ngữ`, `表現`
   - `prefix`: `pref`, `prefix`, `tiền tố`, `接頭辞`
   - `suffix`: `suf`, `suffix`, `hậu tố`, `接尾辞`
   - Giá trị không nằm trong bảng (ví dụ `prep` — trong `core.lexeme` không có `preposition` riêng, hay text tự do) → trả `null` (vẫn khớp theo mặt chữ bình thường, không gây lỗi).
4. **Chuẩn hóa cách đọc (`reading`):**
   - Tách theo dấu cách, phẩy, chấm phẩy, dấu gạch chéo, `・`, `、` (vd `"ささえる つかえる"` → `['ささえる', 'つかえる']`).
   - Lưu cả dạng gốc và dạng quy đổi `toHiragana(token)` (dùng `wanakana` đã có sẵn) để so khớp đúng ngay cả khi file ghi Katakana (`チャーハン`) còn DB ghi Hiragana hoặc ngược lại.

### 3.2. Bước 2 — Batch SQL đối soát ứng viên (`item-import-lookup.repository.ts`)

Thiết kế tận dụng trực tiếp các **B-tree index hiện có** trên DB production (đã xác minh bằng `pg_indexes`):
- `core.lexeme`: `lexeme_lemma_lookup (language_id, lemma)`, `lexeme_lemma_lower_prefix (lower(lemma) text_pattern_ops)`, `lexeme_reading_lookup (language_id, reading)`.
- `core.lexeme_form`: `lexeme_form_lookup (kind, form_text, lexeme_id)`, `lexeme_form_text_lower_prefix (lower(form_text) text_pattern_ops)`.

#### Query 1 — Tìm toàn bộ ứng viên lexeme cho cả batch trong 1 lần gọi DB
Gom tập giá trị duy nhất `uniqueExactWords` và `uniqueLowerWords` từ batch (tối đa 500 từ):
- **Nhánh 1 (`match_source = 1` — khớp `core.lexeme.lemma`):**
  - Với JA (`language_id = 2`): `l.language_id = 2 AND l.lemma = ANY($exactWords::text[])` (ăn thẳng B-tree `lexeme_lemma_lookup`).
  - Với EN (`language_id = 1`): `l.language_id = 1 AND lower(l.lemma) = ANY($lowerWords::text[])` (ăn B-tree `lexeme_lemma_lower_prefix`, hoặc kiểm chứng `EXPLAIN ANALYZE` bằng `UNION ALL` với `l.lemma = ANY(...)` nếu planner không dùng `text_pattern_ops` cho `= ANY` — sẽ xác minh thực nghiệm ở Task 2!).
- **Nhánh 2 (`match_source = 2` — khớp `core.lexeme_form.form_text`):**
  - Bắt các dạng viết khác kanji hoặc biến thể chữ (như `支える` trên lexeme `閊える`, `喰べる` → `食べる`).
- **Nhánh 3 (`match_source = 3` — khớp `core.lexeme.reading`):**
  - Chỉ áp dụng cho `language_id = 2` khi từ nhập vào chỉ gồm kana (`kanaWords`), ăn B-tree `lexeme_reading_lookup`.
- **Điều kiện lọc sạch (đồng nhất với `DictionarySearchRepository`):**
  - `l.language_id = ANY($allowedLanguageIds::smallint[])`
  - `NOT (l.language_id = 2 AND coalesce(l.attributes->>'wikt_pos', '') = 'romanization')`
  - `EXISTS (SELECT 1 FROM core.sense s WHERE s.lexeme_id = l.id)` (không chọn lexeme rỗng).
- **Metadata đi kèm mỗi ứng viên để xếp hạng:**
  - `lexeme_id`, `language_id`, `lemma`, `reading`, `pos`, `frequency_rank`, `match_source`, `matched_key`.
  - `is_jmdict` (`src.code = 'jmdict'`).
  - `has_vi_gloss` (`EXISTS` trên `core.sense_gloss` với `language_id = 3`).
  - `en_learner_rank` (hạng nhỏ nhất trong `serve.english_sense_priority` khi run `en-m10.5-v1` active — khớp chính xác thứ tự M10.5 cho `bank`, `go`...).

#### Xếp hạng chọn 1 `lexeme_id` duy nhất cho từng dòng (trong RAM, tất định)
Với mỗi dòng input có ít nhất 1 ứng viên lexeme:
1. **Khớp từ loại (`pos`):** Nếu dòng có `normalizedPos !== null` và có ít nhất 1 ứng viên có `candidate.pos === normalizedPos` → lọc chỉ xét nhóm khớp `pos` (`pos_matched = true`). Nếu không có ứng viên nào khớp `pos` → giữ nguyên toàn bộ ứng viên (`pos_matched = false`, fallback theo mặt chữ).
2. **Xếp thứ tự ứng viên trong tập đã lọc:**
   - Ưu tiên khớp `reading` (nếu user gửi `reading`):
     - Hạng 0: khớp phần tử đầu tiên trong danh sách `reading` của user (sau chuẩn hóa kana).
     - Hạng 1: khớp phần tử tiếp theo trong danh sách `reading`.
     - Hạng 2: không khớp hoặc user không gửi `reading`.
   - Ưu tiên nguồn chuẩn:
     - JA: `is_jmdict DESC`
     - EN: `(en_learner_rank IS NOT NULL) DESC`
   - Ưu tiên khớp trực tiếp: `match_source ASC` (`lemma` < `form_text` < `reading`).
   - Ưu tiên có nghĩa tiếng Việt: `has_vi_gloss DESC`.
   - Ưu tiên mức phổ biến: `frequency_rank ASC NULLS LAST`, sau đó `en_learner_rank ASC NULLS LAST`.
   - Tie-breaker cuối cùng: `lexeme_id ASC`.

#### Query 2 — Batch chọn 1 `sense_id` tốt nhất + `meaning_vi` + `concept_id`
Cho tập `winningLexemeIds` duy nhất:
- Áp dụng đúng quy tắc xếp hạng sense hiện hành:
  - **EN (`language_id = 1`):** giống [EnglishPriorityRepository](../../src/dictionary/repositories/english-priority.repository.ts) — `curated_order ASC NULLS LAST`, `has_vi_translation DESC`, `restricted ASC`, `specialized ASC`, `sense_no ASC`, `sense_id ASC`.
  - **JA (`language_id = 2`):** giống [JapanesePriorityRepository](../../src/dictionary/repositories/japanese-priority.repository.ts) — `has_vi_translation DESC`, `curated_order ASC NULLS LAST`, `restricted ASC`, `specialized ASC`, `sense_no ASC`, `sense_id ASC`.
- Chọn dòng `rn = 1` mỗi `lexeme_id`, đồng thời lấy:
  - `concept_id`: từ `core.sense_concept` + `core.concept` có `status = 'curated'` và `confidence >= 0.7` (giống [SenseLookupRepository.findManyByIds](../../src/collections/repositories/sense-lookup.repository.ts)).
  - `meaning_vi`: `COALESCE(vi.text, en.text, x.lemma)` (cắt gọn an toàn nếu vượt quá giới hạn DB nếu có, giữ nguyên chuẩn của `DeckRepository`).
  - `meaning_source`: `'machine'` nếu lấy từ gloss VI máy chưa duyệt, ngược lại `'source'`.

#### Query 3 (chỉ chạy khi cần) — Phân biệt `language_not_in_profile` vs `not_in_dictionary`
- Chỉ chạy nếu còn dòng chưa khớp VÀ hồ sơ học chỉ bật 1 trong 2 ngôn ngữ (`EN` hoặc `JA`).
- Kiểm tra nhanh các từ miss trên ngôn ngữ còn lại (`otherLanguageIds`) → nếu có thì gán `reason: 'language_not_in_profile'`, nếu không thì `reason: 'not_in_dictionary'`.

### 3.3. Bước 3 — Khử trùng, Transaction ghi DB & Pre-warm Quiz Bank

1. **Khử trùng trong cùng request (trước transaction):**
   - Duyệt theo `index` tăng dần. Nếu `sense_id` đã xuất hiện ở dòng trước đó trong cùng request → đẩy dòng sau vào `skipped_duplicates` (`reason: 'duplicate_in_request'`).
2. **Transaction Prisma (`timeout: 30_000`):**
   - `await lockUser(tx, userId)` (chống race condition khi đổi ngôn ngữ hồ sơ hoặc sửa collection song song).
   - Đọc lại `study_profile` (`primaryLanguageId`, `secondaryLanguageId`) và kiểm tra lại `assertLanguagesInProfile` với toàn bộ ngôn ngữ của các từ sắp ghi.
   - **Nếu là `POST /v1/collections/import` (tạo bộ mới):**
     - Nếu `dedupedMatched.length === 0` → throw `DomainException('IMPORT_NO_MATCHED_ITEMS', ..., 422, details)` trước khi tạo bất cứ bản ghi nào.
     - Tạo `collection` mới (`id = uuidv7()`, `kind = 'personal'`, `itemCount = dedupedMatched.length`).
     - `startPosition = 0`.
   - **Nếu là `POST /v1/collections/:collectionId/items/import` (bộ có sẵn):**
     - Đọc lại collection (xác nhận sở hữu + chưa archive) và tập `existing anchorSenseId` trong collection.
     - Lọc bỏ từ đã có trong sổ → đẩy vào `skipped_duplicates` (`reason: 'already_in_collection'`).
     - Nếu còn `0` từ cần thêm → kết thúc transaction sạch, trả `added_count: 0`.
     - Tính `startPosition = max(position) ?? 0`, kiểm tra `startPosition + toInsert.length <= MAX_POSITION`.
   - Ghi hàng loạt (`createMany`):
     - `tx.collectionItem.createMany(...)` (`meaningVi`, `meaningSource`, `note`, `status`, `position: startPosition + idx + 1`).
     - `tx.collectionItemFace.createMany(...)` (`role: 'primary'`, `senseId`, `languageId`).
     - `tx.srsState.createMany(...)` (`state: 'new'`, `dueAt: now` — **1 state recognize/face theo M6.3**).
     - Với bộ có sẵn: `tx.collection.update({ data: { itemCount: { increment: toInsert.length } } })`.
3. **Pre-warm Quiz Bank (M11.5) — không chặn request:**
   - Sau khi transaction commit, gọi `quizBankRepo.enqueueBatchImportedSenses(senses)` (method mới):
     - Chỉ enqueue ở **`priority = 50`** (không dùng quota `priority = 10` dành cho người thêm từ lẻ).
     - Giới hạn tối đa **100 sense/lần import** để không làm ngập hàng đợi worker DeepSeek/GLM.
     - Bọc `try/catch` + `logger.warn` — lỗi pre-warm tuyệt đối không làm fail request import.

## 5. Kế hoạch kiểm thử (Test Matrix)

### 5.1. Unit Tests (`pos-normalizer.spec.ts` & `items-import.service.spec.ts`)
1. **Chuẩn hóa từ loại & reading:**
   - Map đúng alias EN (`n`, `v`, `vi`, `vt`, `adj`, `adv`, `prep` → `null`), VI (`danh từ`, `động từ`, `tính từ`, `trạng từ`), JA (`名詞`, `動詞`, `形容詞`, `形容動詞`).
   - Tách `reading` kiểu Mazii `"ささえる つかえる"` → `['ささえる', 'つかえる']`; chuẩn hóa Katakana `チャーハン` khớp với Hiragana `ちゃーはん`.
   - `source_type = 'kanji' | 'grammar' | 'sentence'` → bị đẩy sang `not_found` (`unsupported_type`) trước khi gọi repo.
2. **Xếp hạng đối soát:**
   - Khớp đúng `(word + pos)` thắng từ cùng mặt chữ nhưng khác `pos` (vd `go + noun` chọn danh từ thay vì động từ).
   - Fallback khi lệch `pos`: gửi `豪快 + pos='noun'` nhưng DB chỉ có `adjective` → vẫn khớp `豪快 (adjective)` với `pos_matched: false`.
   - `支える` + `reading: "ささえる つかえる"` → ưu tiên khớp `ささえる` (đứng đầu + tần suất cao hơn).
   - Từ tiếng Anh đa nghĩa (`bank`, `go`) không có `pos` → chọn đúng lexeme/sense theo thứ tự M10.5.
3. **Khử trùng & Giới hạn:**
   - 2 dòng trong cùng request resolve về cùng `sense_id` → thêm 1 dòng, dòng 2 vào `skipped_duplicates` (`duplicate_in_request`).
   - Từ đã có trong collection đích → vào `skipped_duplicates` (`already_in_collection`), không tăng `item_count`.
   - `POST /v1/collections/import` khi 100% `not_found` → throw `422 IMPORT_NO_MATCHED_ITEMS`, không tạo collection mới.
   - `POST /v1/collections/:id/items/import` khi 0 từ mới (toàn trùng / không tìm thấy) → trả `201` với `added_count: 0`, không lỗi.
   - Từ thuộc ngôn ngữ ngoài hồ sơ (nhập EN vào hồ sơ JA-only) → vào `not_found` với `reason: 'language_not_in_profile'`.
   - `status: 'known'` được lưu đúng vào `collection_item.status`.
   - Pre-warm Quiz Bank chỉ gọi `enqueueBatchImportedSenses` (priority 50), lỗi pre-warm không làm fail import.

### 5.2. E2E PostgreSQL (`test/collections-import.e2e-spec.ts`) & Kiểm chứng thực tế
- Kiểm tra toàn bộ luồng HTTP + DB thật:
