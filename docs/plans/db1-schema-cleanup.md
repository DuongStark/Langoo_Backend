# Kế hoạch DB1 — Dọn schema & chốt nguồn sự thật

> Trạng thái: **đã triển khai 2026-10-01 (chờ review)** — chủ dự án chốt: xử lý trực tiếp trên **DB VPS**,
> DB local là bản backup. DB1 không đổi hành vi app, không cần sửa code backend.
> Thuộc lộ trình DB (DB1–DB5) đã đề xuất trong PROGRESS.

## 1. Phạm vi

| Nhóm | Nội dung |
| --- | --- |
| A. Khoá & toàn vẹn | Thêm PK surrogate `id` cho `staging.wn_example`, `staging.wn_relation` — 2 bảng duy nhất trong toàn DB chưa có khoá chính |
| B. Metadata curation | `core.concept` thêm `reviewed_by`/`reviewed_at` + CHECK cặp; `core.sense_concept_candidate` thêm `decision_run_id` (FK `mapping_run`) + partial index phục vụ rollback theo lô |
| C. Ngữ nghĩa | `COMMENT` diễn giải: `sense_concept.verified` (true = nguồn chuẩn WordNet/OMW hoặc người duyệt), `concept.status` (draft → review → curated/rejected), `reviewed_by` là tham chiếu logic `app.users.id` (không FK) |
| D. Tài liệu | Regenerate `CSDL-THAM-CHIEU.md`; sửa quy ước số migration sai trong CONTEXT/README (đang ghi 001–025 / next 026) |
| E. Vận hành | Backup VPS trước migration; áp VPS trước rồi local full (để regenerate tài liệu); **không** áp cloud Prisma (đang là DB demo) |

## 2. Quyết định đã chốt

- **D1** — PK staging: surrogate identity (`GENERATED BY DEFAULT`) vì nguồn WordNet không có khoá tự nhiên ổn định; COPY/insert cũ không đổi.
- **D2** — Không đổi enum `sense_concept_candidate.decision` (giữ `uncertain`; chưa thêm `deferred` — kế hoạch mapping giữ `pending` + lý do trong evidence).
- **D3** — `concept.reviewed_by` **không FK** sang `app.users` (bất biến "core không tham chiếu app"), giống `sense_gloss.reviewed_by`.
- **D4** — Không sửa file migration đã chạy; số mới **031/032**; 028 để trống (dành auth email); tài liệu cập nhật theo thực tế.
- **D5** — VPS apply trước (đã backup), local full apply sau để regen tài liệu; cloud demo không apply.

## 3. Các bước

1. Viết migration `031_staging_pks.sql`, `032_curation_metadata.sql` + plan này.
2. Validate trên `langoo_test` bằng `npm run db:test:reset` (dựng lại từ dump nền 001–025 rồi áp tới 032).
3. Push → CI xanh (e2e chạy trên DB reset có đủ migration).
4. VPS: chạy backup → pull code → `npx tsx scripts/db/migrate.ts` với URL nội bộ → verify.
5. Local full: `npm run db:migrate` → regenerate `CSDL-THAM-CHIEU.md` → đồng bộ 2 repo.
6. Cập nhật PROGRESS/CONTEXT/README.
