# Kế hoạch M2.2 — Đăng nhập Google (OAuth2 · ID token)

> **Trạng thái: đã triển khai (chờ review).** Chủ dự án đã duyệt "OK" ngày 2026-09-28; xem nhật ký trong PROGRESS.md.
> Ngày đề xuất: 2026-09-28. Chốt qua bộ câu hỏi cùng ngày: **Google only · ID token từ SDK · tự động liên kết theo email**.

## 1. Mục tiêu

- Thêm luồng đăng nhập/đăng ký bằng Google cho app & web: client lấy **ID token** từ Google
  Sign-In SDK → gửi backend → backend xác minh (chữ ký JWKS, `iss`, `aud`, `exp`, `nonce`)
  → cấp **access/refresh token nội bộ** giống `POST /auth/login` (dùng nguyên `user_session`).
- Tự động liên kết: email Google đã xác thực trùng tài khoản password → thêm identity Google
  vào tài khoản cũ, không tạo user mới.
- **Không cần migration**: `app.user_identity` đã cho `provider='google'` (CHECK 017) và có
  `email_verified_at`.

## 2. Endpoint mới

### `POST /v1/auth/oauth/google`

| | |
| --- | --- |
| Auth | Không (đây là luồng đăng nhập) |
| Request | `{ id_token: string, nonce?: string, device?: { platform, app_version? } }` |
| Response `200` | `{ user, access_token, refresh_token, expires_in }` — **đúng shape `AuthResultDto`** như login/register |
| Lỗi | `401 AUTH_OAUTH_TOKEN_INVALID` (sai chữ ký/hết hạn/sai iss·aud/nonce lệch) · `403 AUTH_OAUTH_EMAIL_UNVERIFIED` · `403 AUTH_ACCOUNT_LOCKED` / `AUTH_ACCOUNT_DELETED` · `503 AUTH_OAUTH_NOT_CONFIGURED` (chưa cấu hình client ID) · `400 VALIDATION_FAILED` |

Quy ước nonce: nếu token chứa `nonce` thì request **bắt buộc** gửi `nonce` khớp; ngược lại bỏ qua.

## 3. Luồng xử lý (trong 1 transaction)

1. Verify ID token qua Google JWKS → `{ sub, email, email_verified, name, picture, nonce }`
   (thư viện chính chủ, xem §5). Mọi lỗi verify → `AUTH_OAUTH_TOKEN_INVALID`.
2. `email_verified !== true` → `403 AUTH_OAUTH_EMAIL_UNVERIFIED` (không tin email chưa xác thực).
3. Tìm `user_identity (provider='google', provider_uid=sub)`:
   - **Có** → user cũ; `assertUserActive`; cập nhật `last_login_at`; tạo session + device.
   - **Chưa** → tìm `users` theo `lower(email)`:
     - **Có user** → **auto-link**: thêm identity Google (`email_verified_at = now()`);
       cập nhật `last_login_at`; tạo session + device.
     - **Chưa có user** → tạo `users` (email, display_name = `name`, avatar_url = `picture`)
       + `user_identity` Google + `user_settings` mặc định + session + device
       (giống hệt `register`).
4. Đua tạo đồng thời (2 request cùng `sub`/cùng email): bắt unique violation (`users.email`,
   `user_identity(provider,provider_uid)`) → đọc lại và đi nhánh "đã tồn tại" (retry 1 lần).
5. Cập nhật `avatar_url` chỉ khi user chưa có (không ghi đè ảnh user tự đổi sau này).

Token/session dùng đúng hạ tầng hiện có: refresh opaque 32 byte chỉ lưu SHA-256, session
`user_session`, TTL theo `JWT_ACCESS_TTL` / `JWT_REFRESH_TTL_DAYS`.

## 5. Thư viện đề xuất (cần duyệt)

- **`google-auth-library` (chính chủ Google)** — `OAuth2Client.verifyIdToken({ idToken, audience })`:
  tự tải/cache JWKS, xoay khoá, kiểm `iss`/`aud`/`exp`. Hỗ trợ CJS.
- Phương án thay thế nếu bạn muốn nhẹ hơn: `jose` + `createRemoteJWKSet` (tự code nhiều hơn ~30 dòng).

## 6. Kiểm thử

- **Unit verifier** (mock thư viện): map claims → `GoogleIdentity`; token lỗi/hết hạn → 401; sai
  audience; nonce lệch → 401; chưa cấu hình client ID → 503.
- **Unit service** (mock Prisma): tạo user mới đủ đồ (settings/session/identity); Google login lần
  2 không tạo trùng; auto-link tài khoản password; user locked/deleted → 403; email chưa verify →
  403; race unique violation → retry thành công.
- **E2E** (`test/auth-oauth.e2e-spec.ts`, DB `langoo_test`, override verifier bằng stub qua DI):
  - login lần đầu → tạo `users` + `user_settings` + `user_identity(google)` + session;
  - login lần hai → cùng `user.id`, session mới;
  - email trùng tài khoản password → liên kết, login password **và** Google đều vào một user;
  - access token trả về gọi được `GET /auth/me`;
  - token không hợp lệ (stub ném lỗi) → 401; nonce lệch → 401.
- Chạy đủ: `npm run lint`, `npm run build`, `npm run test`, `npm run db:test:reset && npm run test:e2e`.

## 7. Rủi ro & ngoài phạm vi

- **Auto-link**: chấp nhận rủi ro do đăng ký hiện **chưa xác thực email** (ai đó đăng ký trước
  email của bạn bằng password thì lần bạn đăng nhập Google sẽ gộp chung tài khoản đó). Giảm thiểu:
  chỉ link khi Google báo `email_verified=true`. Đề xuất bổ sung **xác thực email** vào M12.
- **Apple Sign In** (bắt buộc cho iOS App Store nếu app có social login khác): **backlog**, làm sau.
- Facebook/Zalo: cần migration 028 (CHECK provider) — backlog.
- Rate limit `POST /auth/oauth/google`: để M12 (cùng `/auth/login`).
- Không có endpoint unlink identity — backlog (chưa cần cho MVP).
