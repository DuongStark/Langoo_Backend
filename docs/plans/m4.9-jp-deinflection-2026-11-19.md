## 1. Mục tiêu & Quyết định thiết kế

1. **Tập trung logic chia thể tiếng Nhật (deinflection) tại 1 module dùng chung ở BE** (`src/common/japanese/jp-deinflect.ts`), port từ `LanGoo-User/src/lib/jp-deinflect.ts` và bổ sung đầy đủ:
   - **Quy tắc bắt buộc §3:**
     - Bảng A: Danh từ + `する` (`応募する` → `応募`, `勉強しました` → `勉強する` → `勉強`, `ほっとする` → `ほっと`).
     - Bảng B ★ (mới): Tính từ đuôi `な` (`親切な` → `親切`, `いい加減な` → `いい加減`) và tính từ đuôi `い` dạng `く` (`細く` → `細い`, `まぶしく` → `まぶしい` → từ điển trả `眩しい`).
     - Bảng C/D/E: Động từ thể `て`/`た`, `ます`, `ない`, `ている`, khả năng/bị động/sai khiến, điều kiện, ý chí, `です`/`だった`, bất quy tắc (`する`, `来る`).
   - **Quy tắc mở rộng §4.3 (cụm câu nói có `する`):** `してくれ` / `してください` / `してくれる` → `[S, S + 'する']`, `てくれ` / `てください` → `[S + 'て']` (`勘弁してくれ` → `勘弁`).
   - **Quy tắc mở rộng §4.4 (chỉ cho M5.3 Import — file bị cụt chữ cuối):** khi cả exact lẫn deinflection trượt mà dòng có `reading` kana hợp lệ, tra theo `reading` và chỉ nhận khi có **duy nhất 1 lexeme** có `lemma.startsWith(word)` (`引っ越` + `ひっこし` → `引っ越し`).
2. **Giải đáp & Chốt 3 câu hỏi §8 của FE:**
   - **POS suru-verb:** DB lưu 15 giá trị `core.lexeme.pos` (`noun`, `adjective`, `adverb`, `verb`…). Dùng `expectedPos` làm tiêu chí ưu tiên xếp hạng mềm (không loại cứng).
   - **Tên trường phản hồi thống nhất:** `deinflected_from: string | null` (`null` khi khớp chính xác; chuỗi gốc khi khớp qua deinflection/reading-prefix) ở cả `ImportAddedItemDto` lẫn `SearchHitDto`. Tương thích ngược hoàn toàn với FE hiện tại.
   - **Triển khai cùng đợt cả Import lẫn Search/Suggestions:** để FE có thể xóa ngay `useDeinflectionSearch` và giảm từ 5–7 request (~550ms) xuống 1 request (~160ms).
3. **Nguyên tắc an toàn & Hiệu năng:**
   - **Khớp chính xác luôn chạy trước và thắng tuyệt đối** (`みんな`, `板`, `きれい`, `する` không bị cắt đuôi).
   - **Chỉ nhận ứng viên có thật trong DB** (1 câu SQL batch `ANY(...)` ăn B-tree index `lexeme_lemma_prefix` + `lexeme_form` + `lexeme_reading_lookup`).
   - **0 migration DB**, **0 package npm mới**.
