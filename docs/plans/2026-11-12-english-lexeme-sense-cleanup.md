# English lexeme/sense cleanup — implementation plan

**Date:** 2026-11-12  
**Repo:** `DuongStark/Langoo_Backend`  
**Scope:** English (`language_id = 1`) first; then other target languages.

---

## 1. Mục tiêu

Làm sạch và giảm số lượng **active lexeme/sense** tiếng Anh mà không phá vỡ dữ liệu app đang tham chiếu.

Kết quả mong muốn:

- Mỗi từ có một mục chính rõ ràng.
- Các dạng biến thể (`ran`, `running`, `runs`) nằm trong `lexeme_form`, không phải lexeme riêng.
- Các sense trùng nghĩa được gộp.
- Từ rác/sai format bị đánh dấu `junk`, không hiển thị.
- Ảnh, deck, collection, SRS, search history không bị vỡ.
- Có audit trail cho mọi quyết định gộp, kể cả quyết định do LLM hỗ trợ.

**Không phải mục tiêu:** xóa cứng hàng loạt hoặc đánh lại ID.

## 3. Nguyên tắc

1. **Không hard-delete.**
2. **Không đánh lại ID lexeme/sense.**
3. Mọi merge là **soft merge + redirect**:
   - `status = active | merged | junk | rejected`
   - `merged_into_lexeme_id`
   - `merged_into_sense_id`
4. App chỉ đọc bản `active`.
5. LLM chỉ **adjudicate** cặp nghi ngờ; không sinh nghĩa mới, không tự xóa.
6. Không merge chỉ vì cùng lemma; phải cùng nghĩa/POS/concept.
7. Làm deck trước, top frequency sau, full DB cuối.

## 4. Schema changes

Migration mới, không rewrite schema hiện có.

### `core.lexeme`

```sql
ALTER TABLE core.lexeme
  ADD COLUMN normalized_lemma text,
  ADD COLUMN search_key text,
  ADD COLUMN status text NOT NULL DEFAULT 'active'
    CHECK (status IN ('active','merged','junk','rejected')),
  ADD COLUMN merged_into_lexeme_id bigint REFERENCES core.lexeme(id),
  ADD COLUMN merge_reason text,
  ADD COLUMN merged_at timestamptz;

CREATE INDEX lexeme_normalized_lookup
  ON core.lexeme (language_id, normalized_lemma, pos)
  WHERE status='active';
```

### `core.sense`

```sql
ALTER TABLE core.sense
  ADD COLUMN status text NOT NULL DEFAULT 'active'
    CHECK (status IN ('active','merged','junk','rejected')),
  ADD COLUMN merged_into_sense_id bigint REFERENCES core.sense(id),
  ADD COLUMN merge_reason text,
  ADD COLUMN merged_at timestamptz;

CREATE INDEX sense_active_lookup
  ON core.sense (lexeme_id)
  WHERE status='active';
```

### Audit tables

```sql
CREATE TABLE core.cleanup_run (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  job text NOT NULL,
  model text,
  prompt_version text,
  started_at timestamptz NOT NULL DEFAULT now(),
  finished_at timestamptz,
  stats jsonb NOT NULL DEFAULT '{}'::jsonb
);

CREATE TABLE core.cleanup_decision (
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  run_id bigint REFERENCES core.cleanup_run(id),
  entity_kind text NOT NULL CHECK (entity_kind IN ('lexeme','sense')),
  left_id bigint NOT NULL,
  right_id bigint NOT NULL,
  decision text NOT NULL,
  confidence real CHECK (confidence BETWEEN 0 AND 1),
  reason text,
  method text NOT NULL,
  model text,
  prompt_sha256 text,
  evidence jsonb NOT NULL DEFAULT '{}'::jsonb,
  reviewed_by bigint,
  reviewed_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX cleanup_decision_queue
  ON core.cleanup_decision (decision, confidence);
```

### Level/frequency

- Giữ `lexeme.frequency_rank`.

## 5. Quy tắc junk

Đánh dấu `junk`/`rejected`, không xóa:

- lemma rỗng, chỉ ký tự/số/URL/code;
- lỗi OCR rõ ràng;
- entry không có definition, gloss, concept, example;
- biến thể hình thái của lexeme khác;
- trùng chính xác sau normalize;
- sense trùng definition/concept trong cùng lexeme;
- dữ liệu sai ngôn ngữ (ví dụ ký tự Nhật trong English);
- entry không đủ tin cậy từ nguồn.

**Không đánh junk** chỉ vì ít gặp. Từ hiếm vẫn có thể hợp lệ.

## 6. Pipeline

### Bước 0 — Snapshot

- Snapshot DB hoặc schema/table copy.
- Ghi row counts trước cleanup.
- Chạy dry-run trên staging.

### Bước 1 — Normalize

Script: `scripts/cleanup/01-normalize.ts`

- Unicode NFC
- lowercase
- trim, gộp whitespace
- chuẩn hóa dấu nháy, hyphen
- bỏ URL/HTML/control chars
- `normalized_lemma`, `search_key`
- chuẩn hóa POS

### Bước 2 — Rule junk

Script: `scripts/cleanup/02-junk.ts`

- Rule-based, không LLM.
- Ghi `status`, `merge_reason`, audit counts.
- Chạy trên English trước.

### Bước 3 — Forms

Script: `scripts/cleanup/03-forms.ts`

- Dùng lemmatizer/WordNet/dictionary forms.
- Map:
  - plural → singular
  - verb tense → base
  - comparative/superlative → base
- Điền `core.lexeme_form`.
- Soft-merge lexeme biến thể vào lexeme gốc.
- Không dùng LLM cho bước này.

### Bước 4 — Exact duplicate

Script: `scripts/cleanup/04-exact-duplicates.ts`

- Group theo `(language_id, normalized_lemma, pos)`.
- Merge lexeme trùng.
- Trong mỗi lexeme, group sense theo `(definition, concept, gloss)`.
- Merge sense trùng.
- Ghi `cleanup_decision` method `rule`.
- Remap references.

### Bước 5 — Candidate generation

Script: `scripts/cleanup/05-candidates.ts`

Không đưa 488k từ cho LLM. Tạo cặp nghi ngờ:

- normalized lemma gần giống;
- cùng lemma khác POS;
- Levenshtein/trigram;
- definition embedding similarity;
- cùng concept;
- một bên là form của bên kia;
- cùng gloss VI/EN.

Output: `core.cleanup_decision` trạng thái `pending`.

### Bước 6 — LLM adjudication

Script: `scripts/cleanup/06-llm-adjudicate.ts`

Input mỗi cặp:

```json
{
  "left": {"lemma":"...", "pos":"...", "definition":"...", "gloss_en":"...", "gloss_vi":"...", "examples":[]},
  "right": {"lemma":"...", "pos":"...", "definition":"...", "gloss_en":"...", "gloss_vi":"...", "examples":[]}
}
```

Output bắt buộc:

```json
{
  "same_lexeme": "yes|no|unsure",
  "same_sense": "yes|no|unsure",
  "junk_side": "none|left|right|both",
  "confidence": 0.0,
  "reason": "ngắn gọn"
}
```

Quy tắc:

- confidence >= 0.9 + rule đồng ý → auto.
- 0.7–0.9 → review.
- < 0.7 → giữ nguyên.
- Không bao giờ auto xóa; chỉ set `merged_into`/`junk`.
- Lưu model, prompt version, prompt sha, evidence.

### Bước 7 — Apply merge + remap

Script: `scripts/cleanup/07-apply.ts`

- Transaction theo batch.
- Set `merged_into_*`, `status`.
- Remap:
  - `deck_item.anchor_sense_id`
  - `sense_media.sense_id`
  - `example_sense.sense_id`
  - `sense_gloss.sense_id`
  - `sense_concept.sense_id`
  - `app.collection_item`
  - `app.srs_state` / review logs nếu có tham chiếu sense
- Recompute `is_primary`:
  - mỗi lexeme active có đúng 1 primary.
- Không xóa row lịch sử.

### Bước 8 — Verify

Script: `scripts/cleanup/08-verify.ts`

- Count active/merged/junk.
- Không có dangling reference.
- Mỗi active lexeme có ít nhất 1 active sense.
- Mỗi active lexeme có đúng 1 primary sense.
- Deck item vẫn resolve được sense active.
- Ảnh vẫn resolve được.
- So sánh trước/sau.
- Sample 500 cặp merge để review.

## 8. LLM strategy

### Không dùng LLM cho

- normalize
- exact duplicate
- lemmatize forms
- xóa ký tự rác
- đếm/reference

### Dùng LLM cho

- cặp lemma/POS gần nhau nhưng không chắc;
- sense definitions gần nhau nhưng khác gloss;
- entry nghi là junk nhưng còn tín hiệu;
- kiểm tra merge.

### Chống false merge

- 2 model/prompt votes cho cặp confidence trung bình.
- Human review mẫu.
- Không auto merge nếu POS khác.
- Không auto merge nếu concept khác.
- Không auto merge nếu một bên có definition rõ ràng khác.

### Cost control

- Candidate pairs chỉ từ exact/fuzzy/embedding.
- Batch 20–50 cặp/request.
- Không gửi full 488k.
- Ưu tiên deck/top frequency trước.
- Cache theo input hash.

## 12. Risks

- Merge sai nghĩa/polysemy.
- Làm vỡ app reference nếu hard-delete.
- LLM không nhất quán.
- Cost LLM nếu chạy full DB.
- Dữ liệu nguồn thiếu/sai.
- POS/lemma normalization khác nhau giữa nguồn.

Mitigation:

- Soft merge.
- Candidate-only LLM.
- Confidence threshold.
- Human sample.
- Snapshot/rollback.
- Chạy deck trước.
