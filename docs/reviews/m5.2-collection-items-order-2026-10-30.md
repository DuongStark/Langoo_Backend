## Vấn đề và hành vi mới

FE cần xem các item position lớn trước trong collection dài, nhưng API chỉ asc + cursor tốiđa100.
Thêm `GET /v1/collections/:collectionId/items?order=desc&limit=100`; server sort trước LIMIT,
FE lấy ngay trang position lớn nhất rồi tiếp tục cùngchiều bằng `next_cursor`.

- Query `order=asc|desc`, mặc địnhasc. `position,id` cùngchiều, tie-break UUID ổnđịnh.
- Desc continuation: `position < cursor.position OR (position=cursor.position AND id<cursor.id)`.
  Asc vẫn gt/gt. `take=limit+1` và envelope/data/next_cursor giữ nhưcũ.
- Desc cursor có `o:'desc'`; legacy cursor asc giữ hìnhdạng `{p,i}` và vẫnđược dùng cho asc.
  Cursor khácchiều hoặc legacyasc dùngcho desc trả400 VALIDATION_FAILED, FE resettrangđầu khiđổiorder.
- Limit default20/max100, ownership/language/status/profile gates giữnguyên. Khôngsorttheocreated_at:
  nếu user đãchỉnhposition, thứtự phảnánhpositionhiệntại chứ khônghứa mới-thêm-trước tuyệtđối.
