## Kết luận

Có hai hướng thay browser đáng xét:

1. **Native gateway client cho tài khoản Muse web**: phù hợp để thử tận dụng
   tài khoản/quota web đã có, bỏ Chrome thường trực. Có implementation cộng đồng;
   chưa test live trên VPS này, chưa xác minh khả năng AI thực sự xử lý song song.
2. **Meta Model API chính thức**: gọi thẳng Muse Spark, không cần Chrome/VM agent.
   Hỗ trợ effort và token usage native. API dùng key/billing của Model API;
   chưa có bằng chứng grant 1 tỷ token Muse web chuyển được sang Model API.

Nhận định README Muse-Chat-MCP “không có public API” không đủ để kết luận Muse
Spark không có API: phải phân biệt agent Muse web với nền tảng inference Model
API. Tài liệu chính thức hiện công bố Model API.

## 1. Bridge hiện tại có đa luồng không?

- Source đang dùng `MuseDriver` với một `this.page` và promise queue `_queue`.
- Guard của Langoo cũng giới hạn một generation; request concurrent nhận 429.
- Gửi nhiều HTTP request vào endpoint hiện tại **không tạo inference song song**.
- Muốn nhiều tab phải sửa worker theo page/thread riêng; mở nhiều instance Chrome
  với cùng profile gây xung đột lock. Cần kiểm cả đồng bộ session giữa tab.
- Chỉ bật headless không bỏ engine/renderers của Chrome; Xvfb hiện chỉ ~15 MiB.

Nguồn implementation: [Muse-Chat-MCP](https://github.com/duclm1x1/Muse-Chat-MCP),
local pinned upstream `6c00e8cf1bf2fb6718740e0c20d3578fb4c47286`,
`scripts/ops/muse/muse-access.mjs` và `muse-driver.mjs`.

## 2. Native client không cần Chrome thường trực

Tìm thấy [kleprevost/muse-mcp](https://github.com/kleprevost/muse-mcp), fork từ
nikships/muse-cli; đã clone chỉ để đọc source ở `/tmp`, không chạy installer.
Commit đọc: `965cc2f197543a8762d3d7067038da6de962730a`.

- Python client dùng session của tài khoản web, Noise/WebSocket gateway, lấy
  reply qua lịch sử có scope side-chat. Browser chỉ cần cho bước lấy/renew phiên.
- Mỗi MCP invocation tạo/đóng Gateway riêng; không có lock chung cả process.
  Lock send/recv vẫn bảo vệ từng kết nối. Không dùng chung một Noise connection
  cho nhiều frame consumer.
- Vì client độc lập, có thể xây hai worker ở hai side-chat khác nhau. Đây là
  **khả năng ở phía client**, không chứng minh backend Muse chạy hai model task
  đồng thời hoặc throughput tăng gấp đôi.
- Timeout local không hủy task từ xa; “sent” chưa phải server acknowledgement.
  Retry phải đối chiếu job marker/history để không gửi lại một job đang chạy.
- Cần adapter JSON/ID validation/checkpoint của Langoo; repo này không phải
  inference endpoint OpenAI-compatible thay vào runner mà không sửa adapter.
- Không cam kết quota web/billing hoặc giảm latency trước khi test. Vẫn qua
  personal Muse agent, nên thời gian suy luận/agent loop phía server còn nguyên.

Nguồn: [README](https://github.com/kleprevost/muse-mcp#reliability-and-security),
[client](https://github.com/kleprevost/muse-mcp/blob/main/muse_mcp/client.py),
[protocol](https://github.com/kleprevost/muse-mcp/blob/main/docs/PROTOCOL.md).

## 3. Meta Model API chính thức

- Base URL `https://api.meta.ai/v1`; các surface `/chat/completions`, `/responses`,
  `/messages`. Key Model API qua Bearer; model có thể chọn chính xác
  `muse-spark-1.3` / `muse-spark-1.3-contributor`.
- Không phải endpoint loopback 8787 của bridge. Đổi alias model ở bridge không
  biến browser thành API chính thức.
- `reasoning_effort=minimal` hoặc `low` hỗ trợ; `none` không hỗ trợ, trả 400.
  Output budget và billing có tính cả reasoning tokens; estimate output char/4
  của job browser không đo các token này.
- Model API có usage/rate-limit headers. Tài liệu hiện công bố Standard 3.000
  RPM / 4M TPM, Contributor 100 RPM / 3M TPM, theo team; phải kiểm entitlement
  và headers thực của key, không dùng giới hạn này cho Muse web gateway.
- Giá /1M tokens hiện tại: Standard input $1,25 / output $4,25; Contributor
  input $0,10 / output $0,20. Contributor cho phép dùng prompt/output huấn luyện.
  API là usage-based; chưa xác minh credits/free grant của tài khoản này.
- Dùng Muse Code CLI chính thức vẫn cần kiểm auth/billing của Model API; không
  chứng minh quota app Muse web đã được chuyển sang API.

Nguồn chính thức: [overview](https://dev.meta.ai/docs/overview),
[protocols](https://dev.meta.ai/docs/protocols),
[reasoning](https://dev.meta.ai/docs/reasoning),
[pricing/rate limits](https://dev.meta.ai/docs/pricing-rate-limits),
[auth/billing](https://dev.meta.ai/docs/muse-code/auth).

## 4. Snapshot tài nguyên VPS

Đọc bằng SSH: `free -m`, `uptime`, `systemctl show … MemoryCurrent`,
`ps`, `vmstat 1 3`, `/proc/pressure/memory`. Snapshot 07/10, sau job 50 đã xong:

| Metric | Đo được |
| --- | --- |
| RAM total | 1.975 MiB (~2 GiB VPS) |
| RAM available | 429 MiB |
| Swap đã dùng | 328 MiB / 2.047 MiB |
| Chrome service memory.current | ~578 MiB |
| Node bridge memory.current | ~97 MiB |
| Xvfb memory.current | ~15 MiB |
| Load 1m / 5m / 15m | 0,75 / 0,56 / 0,49 |

`memory.current` là cgroup accounting, gồm các trang/cache được tính cho service;
không cộng RSS PostgreSQL để đo tổng vì shared memory bị đếm lặp. Hai mẫu vmstat
sau mẫu tổng lịch sử: swap-in/out = 0, CPU idle 74–75%; chưa có dấu hiệu swap
liên tục ở chính vài giây đo đó. Memory PSI có stall nhỏ, không bằng chứng OOM.
Đây **không phải peak trong lúc pilot chạy** hoặc bảo đảm khi tăng concurrency.

Suy luận: giữ Chrome tốn phần đáng kể bộ nhớ VPS 2 GiB. Tránh nhân đôi browser
instance trên VPS đang phục vụ app/DB; ưu tiên bỏ browser thường trực nếu native
client chạy đúng. Chưa dừng service hiện tại hoặc ảnh hưởng Qwen/DB4.

## 5. Hướng triển khai đề xuất khi làm tiếp

### Ưu tiên nếu muốn dùng quota tài khoản web

1. Spike native gateway trên VPS ở service/storage riêng, giữ browser làm fallback.
2. Chỉ lấy session vào file private; không đưa cookie/token vào chat, Git hoặc
   artifact. Chưa thực hiện bước này trong đợt nghiên cứu.
3. Một worker trước: 10 prompt đại diện, gồm JSON/ID, dài, side-chat mới, timeout,
   scope/context isolation. Marker job riêng + kiểm lịch sử trước retry.
4. Khi pass, thử hai worker/hai side-chat, **mỗi connection một consumer** và
   mỗi chat một job đang chạy. Giữ scheduler/budget chung cho account.
5. A/B cùng workload: concurrency 1 vs 2; đo wall time, latencies, failed/duplicate
   sends, cross-chat mixing, RAM/CPU/PSI và thay đổi usage tài khoản.
6. Gate đề xuất: không trộn output/partial, không duplicate gửi; throughput tăng
   ≥1,5x ở 2 worker mà chất lượng không giảm. Nếu server serialize thì giữ 1.
7. Sau khi native pass, tắt Chrome/Xvfb khi không cần login; giữ profile để renew.
   Không mở 5–10 worker ngay vì quota token không cho biết RPM/concurrency.

### Ưu tiên nếu có API credit/key phù hợp

- Dùng Model API trực tiếp, trước 2–4 requests concurrent + batch theo độ dài,
  `reasoning_effort=low`; so với minimal trên cùng mẫu nếu chất lượng đủ.
- Đọc limit headers, backoff 429; cap native usage/cost trước khi tăng batch.
- Smoke nhỏ bằng key + kiểm bill/credits trước chạy bulk. Chưa gọi API mất phí.
- Chạy lại semantic pilot: Muse UI model revision trước chưa xác định; Model API
  chọn 1.3 không chứng minh chất lượng giống pilot 42/50 hoặc tự sửa lỗi face.
