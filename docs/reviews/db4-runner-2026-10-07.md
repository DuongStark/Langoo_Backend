## 2. Kiến trúc runner

- **Load & bind**: đọc job → verify sha `snapshot`/`pilotManifest` → verify sha từng `entry.bundle` → `parseMappingJobBound` (khớp manifest targetKeys, frozen rendering, `maxContextBytes`).
- **Lock**: `jobs/<jobKey>/lock` (O_EXCL nội dung `{pid}`); pid còn sống → từ chối chạy trùng; pid chết → giành lock (stale-safe).
- **Checkpoint**: job JSON ghi atomic sau mỗi transition (`writeTextAtomic`); attempts append-only, kèm reservation/actualUsage.
- **Cache**: `cache/<provider>/<phase>/<mappingCacheKey>.json` → `{raw, output}` refs; hit = transition `queued→r1_received` / `r1_validated→r2_received` với attempt `kind=cache`, reservation 0 (đúng luật `transitionMappingTarget`).
- **Budget**: `jobBudgetUsage` + reservation trước mỗi dispatch; vượt `maxRequests|maxTokens|maxCostMicrousd` → `job.status=budget_exhausted`, giữ nguyên state đã đạt.
- **Retry**: failure (adapter throw / output sai schema) → attempt `failed` (settled) + **attempt retry mới** có `retryReason` (đúng luật “preceding settled + retryReason”, state `running` luôn có attempt `in_flight`); hết `maxRetries` → target `error` + reason, job chạy tiếp target khác.
- **Recovery sau crash**: state `running` + response durable → validate lại từ raw (không dispatch thêm); `running` + không có raw → attempt `unknown` (giữ reservation) + target `error`; state `received` + raw/validated → hoàn tất transition còn thiếu.
- **Decision (policy v1)**: sau `r2_validated`, mỗi candidate 1 decision: 2 pass cùng `exact`/1 exact → `accept_exact`; cùng `broader|narrower|related` → `accept_nonexact`; cùng `none` → `reject_pair`; còn lại (unresolved/disagreement/>1 exact/uncertain) → `defer` kèm reason. Ghi `decisions/<jobKey>/<targetKey>.json` = `{targetKey, decisions[]}`.
  - Runner validate decision bằng `DecisionSchema` + kiểm lineage (`inputHash`, `outputHashR1/R2`) — **không** gọi `parseMappingDecision` vì bundle chỉ chứa semantic candidate (không có full `MappingCandidate` như fixture). D5 có full candidate khi audit.
- **Kết thúc**: mọi entry `decision_ready` → `job.status=awaiting_audit` (D5 audit/gate). Không ghi DB.

## 3. CLI

```bash
# job mới từ bundles manifest + chạy stub (không quota)
npx tsx scripts/db4/mapping-review.ts --generate \
  --bundles bundles/<gen>/manifest.json --provider stub \
  --job jobs/mapping-review-stub.json --artifact-dir uploads/db4

# chạy tiếp job đã checkpoint
npx tsx scripts/db4/mapping-review.ts --generate --resume \
  --job jobs/mapping-review-stub.json --artifact-dir uploads/db4
```

- `newRun` verify sha snapshot/pilot/item, sort entries theo `targetKey` (pilot placeholder sorted; manifest bundles không sorted theo targetKey), render r1/r2 để chốt `renderedR1/R2`, ghi job atomic (idempotent theo bytes).
- Caps qua env: `DB4_CAP_MAX_REQUESTS` (300), `_TOKENS` (5M), `_COST_MICROUSD` (100k = $0,10), `_OUTPUT_TOKENS` (4096), `_CONTEXT_BYTES` (2MB), `_RETRIES` (1, tối đa 2).
- `--provider openai-compatible` (longcat…) đã mở: env `DB4_PROVIDER_ENDPOINT`, `DB4_PROVIDER_MODEL`, `DB4_PROVIDER_API_KEY` (key **không** ghi vào artifact), mặc định `DB4_PROVIDER_THINKING=off` (longcat: ~17-25s/call thay vì 80s bị cắt JSON).
