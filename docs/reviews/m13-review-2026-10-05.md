## M13-01 — P2: feedback giới hạn theo IP thay vì user

**Vị trí:** `src/feedback/feedback.controller.ts:48–54`,
`src/app.module.ts:27–35,75`.

Kế hoạch D7 và API ghi **10 lần/giờ/user**, nhưng endpoint chỉ dùng
`@Throttle` với global `ThrottlerGuard` mặc định lấy tracker từ IP.
JWT guard của controller không thay tracker này.

**Tái hiện:** bật rate limit thật, dùng cấu hình proxy loopback của M12;
user A gửi 10 feedback từ một IP, user B gửi tiếp từ cùng IP. Sau đó A gửi
11 feedback nữa, mỗi request qua một IP khác.

```text
A / cùng IP:       10 × 201
B / IP của A:       429 RATE_LIMITED
A / 11 IP mới:     11 × 201
```

**Tác động:** user chung mạng chặn lẫn nhau; một user đổi mạng có thể vượt
quota gửi. **Hướng sửa:** tracker cho feedback dựa trên user đã xác thực,
phối hợp đúng thứ tự guard; giữ giới hạn IP của auth/global theo thiết kế.
Test cả nhiều user cùng IP và một user qua nhiều IP.

## M13-02 — P2: cursor mất microsecond, bỏ sót hàng trong các queue

**Vị trí:** `src/common/pagination/time-cursor.ts:14–20,37`,
`src/feedback/feedback.service.ts:127–143,315–320`,
`src/admin/admin-gloss-reports.service.ts:63–94`,
`src/admin/admin-audit.service.ts:51–81`.

DB lưu `created_at` bằng `timestamptz(6)`, nhưng Prisma trả JS Date với
millisecond. Cursor serialize bằng `toISOString()`, rồi query lại bằng
timestamp đã mất phần microsecond. Điều kiện equality + ID không bắt được
các hàng nằm giữa timestamp đã cắt và timestamp gốc.

**Tái hiện:** tạo 3 hàng mỗi queue, đặt cùng `created_at` bằng SQL thật thành
`2030-01-02T12:00:00.123456Z`, gọi list `limit=1`, dùng nguyên `next_cursor`
để lấy trang sau. Cursor thực tế mang `...00.123Z`.

- Admin feedback lọc category riêng và gloss reports: trang 1 có 1 hàng,
  trang 2 rỗng; **2/3 hàng bị bỏ qua**.
- `/me/feedback` và audit: sau hàng đầu, pagination nhảy sang dữ liệu cũ,
  bỏ qua hai hàng fixture còn lại.

**Hướng sửa:** giữ khóa timestamp PostgreSQL đủ 6 chữ số cho cursor và query,
dùng thứ tự/điều kiện keyset thống nhất. Test timestamp cùng millisecond và
cùng timestamp chính xác. Helper cũng được chat/quiz sử dụng; khi sửa cần
hồi quy các consumer đó.

## M13-03 — P2: kiểm tra role/status nằm ngoài transaction cập nhật user

**Vị trí:** `src/admin/admin-users.service.ts:34–66`.

Service đọc target và kiểm tra `role/status` trước transaction; bước ghi sau
đó chỉ có `WHERE id`. Role/status thay đổi trong khoảng này không được kiểm
tra lại, phá điều kiện không khóa admin và không hồi sinh user đã xóa.

**Tái hiện có kiểm soát:** giữ snapshot từ lượt đọc thật; trước khi service
ghi, thực hiện cập nhật DB khác trên target. Request vẫn đi qua controller,
guard, transaction và audit thật.

```text
active user → snapshot → role=admin → PATCH locked:
  200, DB kết thúc với role=admin / status=locked

locked user → snapshot → status=deleted → PATCH active:
  200, DB kết thúc với status=active / deleted_at vẫn có giá trị
```

Điều kiện phát sinh là một thay đổi role/status đồng thời, ví dụ qua
bootstrap/maintenance. **Hướng sửa:** đọc/kiểm tra target dưới row lock trong
transaction, hoặc UPDATE có điều kiện eligibility và kiểm tra số hàng ghi;
ghi audit cùng transaction. Thêm test interleaving như trên.

## M13-06 — P2: ghi ảnh lỗi để lại tệp dở không có metadata

**Vị trí:** `src/feedback/feedback.service.ts:65–73`,
`src/storage/local-storage.service.ts:20–23`.

`storedKeys` chỉ thêm key sau khi `storage.put()` hoàn thành. `writeFile`
có thể tạo/ghi một phần tệp rồi reject; key của lần ghi lỗi chưa nằm trong
danh sách cleanup.

**Tái hiện filesystem thật:** process con dùng `ulimit -f 1`, bắt SIGXFSZ để
nhận lỗi ghi; FeedbackService gọi LocalStorageService với buffer PNG 64KB
vào thư mục `/tmp` riêng.

```text
writeFile:                      EFBIG
FeedbackService:                STORAGE_UNAVAILABLE
Tệp còn lại sau service catch:  1 tệp .png, 1024 bytes
```

Tệp thử được xóa sau khi kiểm tra. **Tác động:** upload thất bại lặp lại làm
tích tụ tệp rác, nhất là khi filesystem đang thiếu tài nguyên.
**Hướng sửa:** cleanup cả key đang được ghi, hoặc storage ghi qua tệp tạm và
dọn khi lỗi; test partial write thật/adapter tạo object rồi reject, ngoài
ca put reject trước khi tạo object đang có.
